# RunWay 1차 MVP 요구사항 정의서

> **2026-10-27 온라인 운영 전제 확정:** 휴대폰 모바일 데이터·핫스팟을 켜고, 워치와 휴대폰이 모두 인터넷에 연결된 환경에서 러닝 서비스를 사용한다. 운동 준비 시 워치↔폰 및 폰↔서버 통신도 확인한다. 인터넷 단절 중 운동 지속·장기 오프라인 기록 수집·재연결 전체 복구는 이번 MVP 지원 범위에 포함하지 않는다. 온라인 요청의 중복·응답 지연·DB 저장 실패 처리는 별도로 필요하다. 배치·ACK 세부는 [173번 확정 계약](api/devices-health.md#173번-온라인-확정-계약)을 따르며, 173에서 승인한 API·저장 계약은 확정 설계로 적용하고 구현 완료 여부와 구분한다.

### 가입 후 초기 설정 (2026-10-27 확정)

가입 성공 후 앱은 초기 설정 페이지로 이동한다. 러닝 수준과 평소 페이스(직접 입력 또는 거리·시간으로 계산)를 모두 입력받아 완료 버튼에서 한 번에 저장한다. 서버 저장 성공 후 홈으로 이동하며, 설정 도중 종료하거나 저장에 실패하면 다음 로그인에서도 설정 페이지로 안내한다. 건강정보 이용 동의·선호 환경·과거 운동 기록은 완료 조건으로 강제하지 않는다. 상세 저장·응답 계약은 [인증·사용자 API의 U01·U07·U15](api/users.md)를 따른다.

## 4. AI 페이스 분석·예측 및 조정

**목표와 안내 페이스는 다음과 같이 구분한다.**

- **평소 페이스: 사용자가 초기 프로필에서 입력한 평소 러닝 속도 정보이며, 특정 러닝의 목표와 구분한다.**
- **이번 목표 페이스: 코스 탐색에서 사용자가 입력하거나 목표 거리·완주 시간으로 계산한 값이다.**
- **최초 목표: 출발 전까지 수정할 수 있고 실제 운동 시작 시 확정한 목표다. 러닝 중과 일시정지 중에는 변경하지 않는다. 코스 러닝의 거리·완주 시간·페이스 환산과 자유러닝 목표 허용 조합은 구분한다. 자유러닝은 목표를 선택 입력하거나 모두 생략할 수 있으며 아래 모드별 AI 정책을 적용한다.**
- **현재 안내 페이스: 초기 전략 또는 러닝 중 AI 조정 결과에 따라 현재 구간에 적용되는 권장 페이스.**
- **AI의 안내 페이스 조정은 최초 목표를 자동으로 변경하지 않는다.**

| 요구사항 ID | 기능명 | 요구사항 내용 | 우선순위 |
| --- | --- | --- | --- |
| PAC-001 | AI 초기 페이스 전략 | 시스템은 코스 탐색에서 설정한 이번 목표 거리·목표 완주 시간과 사용자의 평소 러닝 정보·과거 기록을 바탕으로 초기·구간별 안내 페이스를 제안해야 한다. 과거 기록이 없으면 입력한 러닝 수준·평소 페이스·이번 목표를 참고해야 한다. 목표가 있는 자유러닝은 평지 기준 사전 계획을 생성하고, 무목표 자유러닝은 사전 계획을 생성하지 않는다. 전략 확인 화면에서는 설정된 목표와 해당 모드의 계획 제공 여부를 보여준다. | 높음 |
| PAC-002 | 목표 대비 진행 상황 분석 | 시스템은 러닝 중 실제 페이스와 현재 안내 페이스의 차이를 제공해야 한다. 최초 목표의 진행 계획 대비 시간 차이는 해당 목표와 계획이 있는 경우에만 제공한다. | 높음 |
| PAC-003 | AI 페이스 변화 및 완주 시간 예측 | 시스템은 모드별 HR 예측과 페이스 분석을 수행한다. 남은 거리 등 산출 기준이 있을 때 예상 완주 시간을 제공하고, 최초 목표 완주 시간과의 비교는 해당 목표가 있는 경우에만 제공한다. | 높음 |
| PAC-004 | AI 동적 페이스 조정 | 시스템은 현재 페이스·심박수·운동 부담과 모드별 목표·미래 경사를 바탕으로 MPC를 통해 안내 페이스를 조정한다. 무목표 자유러닝에서는 HR 부담·급격한 페이스 변화 최소화와 가능한 현재 페이스 유지를 기준으로 한다. | 높음 |

| PAC-006 | 운동 부담 및 오버페이스 감지 | 시스템은 현재 페이스와 **현재 안내 페이스**의 차이, 심박수 변화 및 사용자의 러닝 수준·과거 기록을 바탕으로 운동 부담 증가와 오버페이스 여부를 판단해야 한다. **과거 기록이 없는 경우 러닝 수준과 현재 수집 데이터를 기준으로 판단해야 한다.** | 높음 |
| PAC-007 | 페이스 저하 감지 | 시스템은 일시정지 구간을 제외하고 최근 페이스가 **현재 안내 페이스**보다 느린 상태로 일정 시간 지속되는 경우 페이스 저하를 감지해야 한다. | 높음 |

### 러닝 모드별 AI 동작

사용자 확정 정책이다. 자유러닝은 거리·시간·페이스 중 원하는 목표만 선택 입력하거나 모두 생략할 수 있으며, 2개 필수 입력 조건을 두지 않는다.

| 모드 | 출발 전 Pace Plan | Future Grade | 러닝 중 동작 |
|---|---|---|---|
| 코스 지정 러닝 | 실제 코스 전체를 시뮬레이션하여 구간별 계획 생성 | 코스의 실제 미래 경사 | HR Predictor로 30/60/120초 뒤 HR을 예측하고, MPC가 목표 기록·HR 상태·미래 경사를 고려해 추천 페이스 계산. BPM·음성 Cue 제공 |
| 목표가 있는 자유러닝 | 입력 목표를 기준으로 평지 기준 계획 생성 | 0% 가정 | 현재 HR·Speed·Elapsed Time 등을 반영해 후보 Future Speed별 30/60/120초 뒤 HR 예측. MPC가 목표 기록을 최대한 유지하면서 HR 부담이 적은 페이스 선택. BPM·음성 Cue 제공 |
| 목표 없는 자유러닝 | 사전 계획 없음 | 0% 가정 | 현재 HR·Speed 등을 바탕으로 후보 페이스별 미래 HR 예측. MPC는 HR 부담과 급격한 페이스 변화를 최소화하고 가능한 현재 페이스를 유지. 필요 시 감소·유지 등의 실시간 코칭 제공 |

- HR은 심박수, BPM 가이드는 리듬 안내 값이며 서로 구분한다. Future Grade 0%는 미래 경로를 모르는 자유러닝의 예측 가정이다.
- 무목표 러닝의 사전 계획 부재는 생성 대기·실패가 아니다. 계획 생성을 기다리지 않고 시작하며, 러닝 중 측정값에 따라 코칭한다.
- 목표 비교·달성 평가는 입력한 목표에 한해 제공한다. 목표가 없으면 목표 달성·남은 목표 거리·목표 대비 시간 차이를 임의로 만들지 않는다. 예상 완주 시간도 산출 기준이 있는 경우에만 제공한다.
- 목표는 출발 전 수정할 수 있지만 실제 시작 이후에는 고정한다. 수동 BPM 변경은 다음 예측·코칭에 반영하며 영구 고정이나 보정량 누적을 하지 않는다.
- 상세 모델 입력·목표가 일부만 있을 때의 계획 구간과 환산·상충 입력 검증, MPC 가중치·제약·실행 주기, 응답 필드·상태 표현은 구현 계약에서 구체화한다. 모드별 동작 자체는 미결 사항이 아니다.

다음 기능은 현재 정의한 1차·2차 MVP 범위에 포함하지 않으며, 도입 여부와 시점은 추후 검토한다.

## 자동 처리·연결 장애 시 동작

아래는 2026-10-23 사용자 확정 사항이다.
초기 전략·공동 페이스·러닝 중 코칭·기록 비교는 데이터와 상태 변경에 따라 자동 처리하며, 클라이언트 조회가 실행 조건이 되어서는 안 된다.
2026-10-27 사용자 변경에 따라 러닝 서비스는 폰·워치가 온라인인 환경을 전제로 한다. 온라인 응답 지연·ACK 유실은 불변 batch로 제한 재시도하고, 폰 인터넷이 끊기면 실행 불가·기록 미확인 상태를 표시한다. 인터넷 단절 중 운동 지속·장기 기록 복구는 이번 MVP 의무가 아니다. 워치 연결만 끊기고 폰 인터넷은 유지되면 사용자가 폰으로 기록을 인계해 GPS 기록을 계속하고 폰에서 종료·저장한다. 워치 없이 새 운동을 시작하는 기능은 별도의 2차 MVP 후보로 구분한다.

계정 공개·팔로우와 원본 기록·공유 게시물의 경계는 [계정 공개·팔로우 명세](api/users.md)를 따른다. 화면 v10의 공용 코스 이름·자주 만난 장소·기록별 공개 설정은 최신 사용자 결정에 따라 적용하지 않는다.

자유러닝의 목표 거리·시간·페이스는 선택 입력이며 모두 생략할 수 있다. 목표가 있으면 평지 기준 사전 계획을 생성하고, 무목표이면 사전 계획 없이 실시간 코칭을 제공한다. 상세 동작은 위 러닝 모드별 AI 동작을 따른다.

### 알림 제외 — 사용자 확정

- 공개 전환에 따른 팔로우 요청 자동 승인 알림은 보내지 않는다. 공개 전환 화면에서 계정 소유자에게 대기 요청이 모두 자동 승인된다는 안내를 표시한다(2026-11-05, S15P31E105-246·249). 수동 U25 승인 알림은 유지한다.

- 러닝 분석 완료 알림은 보내지 않는다. 결과 화면은 분석 상태가 READY가 되면 최종 결과를 바로 표시한다. 화면 재진입 시 현재 분석 상태와 저장된 결과를 조회한다.

- 오늘의 준비도 결과 도착 알림은 보내지 않는다. 준비도 자동 평가와 화면 결과 표시는 유지한다.
- 참가 응답 마감 임박 알림은 보내지 않는다. 기존 G01의 마감 전날 미응답자 알림 규칙도 제거한다. 그룹런 시작 임박 알림과는 별개다.
- 그룹런 참가·참가 취소에 대한 알림은 보내지 않는다. 참가 상태·인원 갱신과 취소자의 시작 임박 예약 알림 정리는 유지한다.

### 운동 중 즉시 안내 — 일반 소식 알림과 구분

기존 PAC·BPM·GRP·WAT·SYS 요구사항과 자동 처리 설계의 전달 기능이다. 푸시·알림함에 매번 쌓는 것으로 확정하지 않는다.

| 상황 | 대상 | 기본 전달 방향 |
|---|---|---|
| 안내 페이스·목표 BPM 변경 | 본인 앱·워치 | 운동 화면 갱신, 설정에 따른 음성·진동·리듬 적용 |
| 오버페이스·페이스 저하·운동 부담 감지 | 본인 앱·워치 | 코칭 안내. 발행 조건·반복 방지는 [코칭 발행 조건](api/pace-coaching.md#코칭을-보내는-시점)을 따름 |
| 공동 페이스 변경·그룹 격차 발생 | 해당 그룹 참가자 | 그룹 화면·워치 실시간 안내. 알림 대상 범위·빈도 미정 |
| 워치·GPS·심박 수집 끊김 또는 권한 부족 | 영향받은 본인 | 기기 내 상태 표시·필요시 안내. 정상 수집값과 구분 |
| 기록 전송이 계속 실패해 조치 필요 | 본인 | 동기화 상태·재시도 안내. 매번 실패할 때 푸시하지 않는 방향 제안 |

그룹 실제 시작·강제 종료의 상태 반영은 알림 표시 설정과 별개다. 소식 알림을 껐다고 운동 상태 전파를 중단하지 않는다.
연결 복구 중 오래된 페이스·격차 코칭을 뒤늦게 재생하지 않는다.

### 별도 알림을 권하지 않는 상황 — 제안

- 팔로우 거절·취소·언팔로우는 별도 푸시보다 관계 상태에 반영한다. 크루 가입 거절 알림은 사용자가 명시했으므로 포함한다.
- 본인이 한 행동에 대한 서버 응답 성공은 화면에서 안내한다. 같은 내용을 자기 푸시로 중복 발송하지 않는다.
- 일반 측정값 수신·준비도 재계산·데이터 배치 동기화 성공·매번의 BPM 변경은 일반 소식 알림으로 누적하지 않는다.

### 공통 처리와 남은 결정

- 그룹런 취소·시간 변경·참가 취소 시 예약된 시작 임박 알림을 취소하거나 재계산한다. 발송 직전 현재 상태와 수신 자격을 다시 검사한다.
- 비공개 게시물의 댓글·좋아요 알림도 수신자의 현재 접근 권한을 검사한다. 삭제된 댓글·게시물은 연결 시 현재 상태를 안내한다.
- 이벤트별 중복 제거는 `notifications.dedupe_key` UNIQUE로 적용한다(S15P31E105-458). 실시간 상태 반영(S10 등)과 알림함 소식을 구분한다.
- 2026-11-06 사용자 확정(S15P31E105-458): 앱 내 알림함 계약은 종류·발생 시각·`target_id`·message·읽음(`read_at`)·목록/전체 읽음 API다. 보관 기간·단건 읽음 API·앱 밖 푸시는 포함하지 않는다.
- 2026-11-05 사용자 확정(S15P31E105-249) + 458: 공개 계정 새 팔로워·비공개 새 팔로우 요청·수동 승인 알림은 `notifications.community`를 따른다. false이면 **알림함 행을 만들지 않는다**. 새 설정 항목은 추가하지 않는다. 공개 전환 자동 승인 알림 제외는 유지한다. 크루 알림의 설정 분류(community vs groupRun)는 별도 확정 전까지 community로 구현한다.
- 시작 임박 시점·횟수, 중요 변경 필드, 선택 알림 채택 여부, 요청·알림 목록 화면 진입 위치는 미정이다.

| 앱·워치 | 온라인 운영 환경에서 측정·기록·가이드를 제공한다. 응답 지연·중복 요청은 batch 저장 확인으로 처리하고, 폰 인터넷 연결이 끊기면 서비스 불가 상태를 표시한다. 워치 연결만 끊기면 폰 GPS 기록 인계·종료·저장을 제공하고 코칭·BPM 가이드를 중단한다. 오프라인 운동 지속·전체 기록 자동 복구는 이번 MVP에서 제공하지 않는다. |
| 앱·워치 | 휴대폰·워치 간 운동 제어와 적용 BPM을 일치시키고 중복 명령·오래된 안내의 재적용을 막는다. |
| 서버 | 건강 데이터 반영 후 준비도, 세션 준비 후 모드에 따른 초기 전략(무목표 자유러닝 제외), 측정 데이터 수신 후 코칭·기록 비교·BPM·그룹 순위를 자동 계산하고 전달한다. |
| 서버 | 개인 운동 종료 후 분석·통계·경로 그림을 준비하고, 전원 개인 종료 시 그룹을 자동 종료·정리한다. |
| 서버 | 계정 공개 전환 시 대기 팔로우 요청을 자동 승인하고 관계·접근 권한·팔로워 수를 반영한다. 앱이 개별 승인 API를 반복 호출하지 않는다. |

주기·배치 크기·메시지 스키마·로컬 계산 세부 방식은 별도 설계 대상이다. 서버 분석이 필요한 새 코칭을 연결이 끊긴 기기가 대신 생성하는 것으로 확정하지 않는다.

- 원본 저장·상태 변경 후 실패한 후속 작업과 원 요청을 구분한다. 러닝 종료 후 분석은 실패 시 FAILED로 표시하고 자동 재시도·종료 후 자동 재집계를 하지 않는다. 경로 그림·다른 도메인 알림의 재시도 정책은 별도로 정하며, 실패를 이유로 운동 시작·종료를 다시 실행하도록 요구하지 않는다.
- 종료·동기화·분석 완료를 구분하며 준비 중·부분 데이터·실패·갱신 결과를 표현한다.
- 누적 기록은 이후 개인화·러닝 수준 추정·BPM 특성 갱신에 반영한다. 자기보고 수준과 추정 수준을 구분하며 이미 시작한 세션의 목표를 바꾸지 않는다.

### 173 승인 연동 세부 정책 (2026-10-28)

- 데이터 모델은 현재 운동 상태·필요한 제어 결과·오래된 코칭 차단만 추가한다. 명령 ID는 서버 BIGINT, 미확인 명령은 현재 실행기기 기준, 변경 검사는 단일 상태 버전, 코칭은 기준 버전과 만료 시각으로 처리한다.
- READY/PAUSED BPM 조절은 무음 저장, RUNNING에서만 재생한다. 60~220 정수·1BPM 단위이며 재개 시 최신값을 사용한다.
- 무목표 자유러닝도 현재 심박·운동 데이터에 따른 페이스 코칭을 제공한다. 목표 기반 사전계획만 생략한다.
- 서버 기준 시각과 기기 오차 추정으로 코칭의 최대 20초 신선도를 확인한다. 기기 시계·실제 측정시각을 바꾸지 않는다.
- 코칭은 AI가 필요하다고 판단하거나 코칭 없이 2분이 지난 경우 발행한다. 2분은 실제 시작·재개·마지막 코칭 적용 중 가장 최근 시각부터 계산하며, 서버에 APPLIED로 확인된 시각을 사용한다. 조절이 필요 없으면 유지 안내를 제공하고 BPM을 강제로 바꾸지 않는다. RUNNING·워치 기록·유효 입력 조건과 중복 방지는 [코칭 발행 조건](api/pace-coaching.md#코칭을-보내는-시점)을 따른다.
- 워치·폰 제어는 REQUEST 승인 → 현재 실행기기 적용 → RESULT 저장으로 통일한다. 워치는 항상 폰을 통해 서버와 통신하며, 폰 인계 후 PAUSE/RESUME/END도 같은 단계를 따른다. 승인과 실제 시작을 구분하되 별도 완료 팝업은 만들지 않는다.
- 종료는 마지막 batch의 서버 저장 확인 후 확정한다. 분석 자동 재시도·실행권·종료 마감 해시·오프라인 복구는 제외한다. 실기기 검증/서비스 구현 완료와 구분한다.

- 폰 인계는 기존 세션의 제어기기만 변경한다. 이전 워치 미확인 결과를 성공으로 바꾸거나 종료를 막는 데 사용하지 않는다. 마지막 폰 batch 저장 확인 후 종료하며 미수신 워치 자료는 결측으로 남긴다. 코스 조회·커뮤니티는 폰 인터넷이 있으면 워치 연결 여부와 무관하게 이용한다.

### 시작 응답 복구와 종료 경계

- 세션 생성 응답이 유실되면 ACTIVE_SESSION_EXISTS의 본인 sessionId로 기존 운동을 조회한다. 새 목표로 자동 덮어쓰지 않는다.
- START 결과가 미확인인 READY 세션은 폰 인계·일반 종료를 하지 않는다. 재연결 후 결과를 재확인하거나 사용자가 S08 ABORT_UNCONFIRMED_START로 관리상 중단한다. 중단은 INTERRUPTED, 분석 FAILED로 남기고 실제 시작/종료시각을 추정하지 않으며 UNKNOWN 이력을 보존한다. 늦은 결과로 재활성화하지 않는다.
- 그룹 자동 종료는 승인된 START가 확정되거나 명시 중단된 뒤 실제 시작 참가자가 모두 종료했을 때 수행한다. 미확정 START가 있으면 자동 종료는 보류하고 그룹장의 강제 종료를 허용한다. 강제 종료 시 미확정 START 세션은 관리상 중단하고, 재연결한 워치는 최신 상태를 확인해 측정·박자를 멈춘다. 늦은 START 성공·미전송 기록의 복구는 제공하지 않는다. 실제 시작이 이미 확인된 참가자의 END·저장은 유지한다.
- 그룹 분석은 실제 시작한 참가자만 대상으로 한다. 미확정 시작은 별도 표시하고 최종 결과 확정을 보류하며, 시작 거절·명시 중단 세션 때문에 분석 완료를 기다리지 않는다.
- 그룹 종료 기준시각은 집계할 측정시각의 경계이고, 업로드 마감은 각 개인 END 확정이다. 개인 END 확정 전 지연 batch를 저장하고 그룹 기준 이후 샘플은 그룹 집계에서 제외한다. 개인 END 후 새 batch는 거절하며 동일 batch의 기존 ACK만 재응답한다.
