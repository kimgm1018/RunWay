# 러닝 준비도(Readiness) 1차 산식

러닝 시작 전 사용자의 최근 상태로 오늘 러닝 준비 정도를 0~100점으로 계산하는 1차 산식이다.
서버는 이 문서대로 계산해 `daily_readiness`에 저장하고 [R02](api/readiness.md#r02-최신-준비도-조회)로 제공한다.

| --- | --- |
| 원본 설계 | S15P31E105-121 "[AI] 러닝 준비도(Readiness) 1차 산식 및 보정 규칙 설계" 결과(팀 Notion "러닝 준비도 1차", 2026-11-02 확인) |
| 서버 구현 | S15P31E105-254, `backend/.../domain/readiness/formula/ReadinessFormula.java` |
| 범위 | 1~6-1절은 원본 설계, 7절은 원본에 없는 부분을 254에서 정한 서버 해석이다. 5절의 Zone 기준·운동 부하 수집과 이력 보정은 S15P31E105-599에서 정했다. 산식을 바꾸면 이 문서와 서버 구현을 함께 고친다. |

## 1. 구성

세 항목을 쓴다. 평가 날짜를 D라 한다.

- **S (Sleep)**: 최근 수면 상태
- **R (Recovery)**: 심혈관 회복 상태(안정시 심박)
- **L (Training Load)**: 최근 훈련 부하

기본은 세 점수의 평균이다. 한 항목이 매우 낮은데 다른 항목이 높아 최종 점수가 과하게 높아지지 않도록 최저 항목 기반 상한을 적용한다.

## 2. 기본 준비도

```text
BaseReadiness = (S + R + L) / 3
예) S 90, R 80, L 70 → 80
```

단순 평균만 쓰면 S 100, R 100, L 20일 때 73.3으로 "양호"가 되어 부자연스럽다. 그래서 6절의 상한을 적용한다.

## 3. 수면 점수 S

수면 부족이 지구력 운동 수행에 악영향을 준다는 연구([PubMed 36472094](https://pubmed.ncbi.nlm.nih.gov/36472094/))를 근거로 한다.
최근 3일을 반영하며 최근일수록 가중치가 크다.

```text
S = 0.5·D0 + 0.3·D1 + 0.2·D2   (D0 = D의 수면 점수, D1 = D-1, D2 = D-2)
```

| 수면 시간 | 점수 |
| --- | --- |
| 7시간 이상 | 100 |
| 6시간 | 70 |
| 5시간 | 40 |
| 4시간 | 10 |
| 4시간 미만 | 0~10 |

예) 7시간 100, 6시간 70, 5시간 40 → S = 50 + 21 + 8 = 79

## 4. 회복 점수 R

오늘 안정시 심박(RHR)을 평소 RHR과 비교한다. 평소보다 많이 높을수록 회복이 덜 된 것으로 본다.

- 오늘 RHR: D의 Daily RHR. 원본 설계는 "하루 중 가장 낮은 연속 30분 평균 HR"이다.
- 평소 RHR: 이전 7일(D-7~D-1) Daily RHR 평균
- 변화율 = (오늘 RHR − 평소 RHR) / 평소 RHR × 100

| 평소 대비 오늘 RHR | 점수 |
| --- | --- |
| +3% 이내 | 100 |
| +3~5% | 90 |
| +5~8% | 80 |
| +8~12% | 65 |
| +12~15% | 50 |
| +15% 초과 | 35 |

예) 평소 60bpm, 오늘 66bpm → +10% → 65

## 5. 훈련 부하 점수 L

Edwards TRIMP로 운동량과 강도를 함께 본다. 심박 Zone별 운동 시간(분)에 Zone 번호(1~5)를 곱해 더한다.

```text
예) Z1 10분·1 + Z2 20분·2 + Z3 15분·3 + Z4 5분·4 = 10 + 40 + 45 + 20 = 115
```

평소 부하는 최근 28일의 주간 부하 평균이다. 최근 7일 부하를 평소 주간 부하로 나눈 비율로 점수를 낸다.

```text
예) 주간 부하 380, 420, 390, 410 → 평소 400. 최근 7일 410 → 비율 1.025
```

| 최근 7일 / 평소 | 점수 |
| --- | --- |
| ≤ 1.0 | 100 |
| 1.0~1.2 | 100~90 |
| 1.2~1.4 | 90~80 |
| 1.4~1.6 | 80~65 |
| 1.6~2.0 | 65~50 |
| > 2.0 | 35 |

구간 안의 값은 선형 보간한다.

### 5-1. Zone 기준과 운동 부하 수집 (S15P31E105-599, 2026-11-10 사용자 결정)

- **계산 위치:** 서버. 산식은 서버 한 곳(`TrainingLoadCalculator`)에만 둔다.
  - RunWay 러닝: 종료 후 분석이 READY로 끝나면 서버가 저장한 러닝 심박 샘플(`running_metric_samples`)로 계산한다. 러닝을 삭제(S09)하면 그 부하를 지운다.
  - 삼성 헬스 운동: 앱이 최근 28일 운동(종류 무관, 심박 기록이 있는 운동)을 읽어 운동마다 "bpm별 머문 초" 요약을 W06 `EXERCISE_HR_SUMMARY`로 올리고 서버가 같은 기준으로 계산한다([W06](api/devices-health.md#w06-samsung-health-데이터-동기화)).
- **샘플 → bpm별 머문 초(서버·앱 공통):** 30~220bpm 유효 샘플을 측정 시각 오름차순으로 보고 같은 시각의 두 번째 이후 샘플은 버린다. 샘플 i의 머문 시간 = `min(다음 유효 샘플 시각 − i 시각, 60초)`, 마지막 샘플은 0. bpm은 반올림(half-up) 정수. 밀리초로 더한 뒤 bpm마다 초로 반올림(half-up)하고 0초인 bpm은 버린다.
- **Zone:** 기록 통계(H06)와 같은 Karvonen 기준. HRR = HRmax − RHR, Zone N = HRR의 (40+10N)%~(50+10N)% + RHR(상단은 다음 Zone, Zone5는 상단 포함). Zone1 하한(50%) 미만 시간은 부하에 넣지 않는다.
  - HRmax: 운동 날짜 이전(포함) 최근 `max_heart_rate` → 최신 값 → `220 − 만 나이`(`users.birth_date`, 운동 날짜 기준).
  - RHR: 운동 날짜 이전(포함) 최근 `rhr_bpm` → 최신 값 → 없으면 0(즉 HRmax 비율 50·60·70·80·90%). 기록 통계는 RHR이 없으면 Zone을 비우지만, 부하는 RHR 없는 회원도 계산하려고 HRmax 비율로 대체한다.
- **운동 1건 부하:** `Σ (Zone N 초 ÷ 60) × N`, 소수 넷째 자리(HALF_UP). 저장 시점의 HRmax·RHR로 한 번 계산하며 이후 RHR이 바뀌어도 다시 계산하지 않는다.
- **하루 부하(`daily_training_load`):** 그 날짜 RunWay 러닝 부하 합 + 그 날짜 삼성 헬스 운동 중 같은 회원의 어떤 RunWay 러닝과도 시간이 겹치지 않는 부하 합. 해당 운동이 없으면 NULL. 도착 순서와 관계없이 같은 결과가 되도록 바뀔 때마다 날짜 단위로 다시 계산한다.
- **날짜:** RunWay 러닝은 시작 시각의 Asia/Seoul 날짜(서버가 회원 시간대를 모름, H06/H07과 같은 MVP 기본), 삼성 헬스 운동은 폰 시간대 시작 날짜다.

## 6. 보정 규칙

M = min(S, R, L)일 때 최종 준비도의 최대값을 제한한다.

### 6-1. 최저 항목 기반 상한

| S/R/L 중 가장 낮은 점수 | 최종 준비도 최대값 |
| --- | --- |
| 70 이상 | 100 |
| 50~69 | 84 |
| 30~49 | 69 |
| 0~29 | 49 |

```text
Readiness = min(BaseReadiness, 상한(M))
```

점수 구간별 표시 등급(`readinessLevel`)과 판단 요인 표시는 원본 설계에서 정리 중이다. 확정 전에는 R02 응답에 포함하지 않는다.

## 7. 서버 해석(S15P31E105-254 확정)

원본 설계에 없는 입력·경계 처리다. 2026-11-02 사용자 확인으로 정했다.

### 7.1 입력

- 입력은 `daily_health_metrics`의 회원별 일별 값만 쓴다. 날짜는 W06 `metricDate`다(워치 심박은 워치 시간대 날짜, 삼성 헬스 심박은 폰 시간대 날짜, 수면은 폰 시간대 기상일).
  - S: `sleep_duration_min`, R: `rhr_bpm`, L: `daily_training_load`(하루 TRIMP 합)
- 오늘 RHR은 W06이 저장한 `rhr_bpm`을 출처와 관계없이 그대로 쓴다. 출처는 RunWay 워치 추정(`ROLLING24H_LOWER_10PCT_MINUTE_MEAN_V2`) 또는 삼성 헬스 심박으로 폰이 계산한 값(`DAILY_LOWER_10PCT_MINUTE_MEAN_V1`, S15P31E105-600)이며 같은 날짜는 워치 값이 우선한다. 둘 다 원본 설계의 "연속 30분 최저 평균"과 다르며, 정의는 [W06 계약](api/devices-health.md)을 따른다. 평소 RHR(이전 7일)에 두 출처가 섞일 수 있고 그만큼 R 점수가 흔들릴 수 있음을 수용했다(2026-11-09 사용자 결정).
- W06은 RHR(워치 또는 삼성 헬스 심박, S15P31E105-600)과 수면(삼성 헬스 기상일 합계, S15P31E105-572)을 저장한다. 수면 날짜는 폰 시간대 기상일이며 RHR의 워치 시간대 날짜와 같은 기기 시간대를 전제로 한다.
- 부하는 5-1절대로 RunWay 러닝 종료 후 분석과 W06 삼성 헬스 운동 요약이 채운다(S15P31E105-599). RunWay 러닝 날짜(Asia/Seoul)와 기기 시간대 날짜가 다른 지역에서는 자정 근처 러닝이 하루 어긋날 수 있다.

### 7.2 경계와 보간

- 수면 점수는 4·5·6·7시간 사이를 선형 보간한다(1시간당 30점). 4시간 미만은 `10 × 시간 / 4`(0시간 0점)다.
- 회복 구간은 상단을 포함한다. +3.0%는 100, +5.0%는 90이다. 평소보다 낮으면(음수) 100이다.
- 부하: 최근 7일 = D-6~D 합, 평소 주간 부하 = D-27~D 합 × 7 ÷ H. H(이력 일수) = min(28, D − 회원의 D 이전(포함) 첫 부하 날짜 + 1)이고 최소 7이다. 첫 부하 날짜는 `daily_training_load`가 NULL이 아닌 가장 이른 날짜다. H = 28이면 원래 정의(28일 합 ÷ 4)와 같다(S15P31E105-599 이력 보정). 비율 1.0·1.2·1.4·1.6·2.0은 아래 구간 값으로 계산하며 2.0 초과는 35다. 구간 판정은 나눗셈 없이 `최근 7일 합 × H ≤ k × 28일 합 × 7`로 비교한다.
- 상한 경계는 M ≥ 70 → 100, M ≥ 50 → 84, M ≥ 30 → 69, 그 밖 49다.
- 항목 점수와 최종 점수는 소수 둘째 자리 반올림(HALF_UP)이다. `readiness_score`는 NUMERIC(7,2)다.

### 7.3 결측과 신뢰도

미측정 값을 0점으로 채우지 않는다. 항목별로 계산 가능 여부를 판정한다.

| 항목 | 계산 조건 | 부족할 때 |
| --- | --- | --- |
| S | D0~D2 중 수면값이 있는 날만 가중치를 다시 나눠 계산 | 3일 모두 없으면 제외 |
| R | D의 RHR이 있고 D-7~D-1 중 3일 이상 RHR이 있음 | 제외 |
| L | D-27~D에 부하 값이 하루 이상 있고 28일 합 > 0. 값 없는 날은 운동하지 않은 날(0) | 제외 |

- 계산된 항목만으로 평균과 최저값을 구한다.
- `readiness_confidence`는 계산된 항목 수다: 3개 HIGH, 2개 MEDIUM, 1개 LOW. 이는 신뢰도이며 준비도 등급이 아니다.
- 계산된 항목이 없으면 결과를 저장하지 않는다. 같은 날짜의 기존 결과는 그대로 둔다.

### 7.4 평가 시점

- W06이 건강값을 저장·갱신한 날짜 D와, D+1~D+7 중 건강 행이 있는 날짜를 커밋 후 별도 스레드에서 평가한다. 처리 순서·잠금·실패 처리는 [readiness.md 자동 평가](api/readiness.md#자동-평가--내부-필수-처리)를 따른다.
- 일별 부하가 바뀐 날짜 D(W06 운동 요약, RunWay 러닝 종료 후 분석·삭제)는 D와 D+1~D+27(부하 28일 창) 중 건강 행이 있는 날짜를 평가한다(S15P31E105-599).

### 7.5 알려진 한계

- 부하 이력이 28일보다 짧은 경우는 7.2의 이력 보정으로 처리한다(S15P31E105-599). 첫 부하 날짜 이전에 실제로 운동했지만 기록이 없던 회원(삼성 헬스에 심박 없는 운동 등)은 이력이 짧게 잡혀 평소 부하가 실제보다 클 수 있다.
- 삼성 헬스 과거 운동은 앱이 처음 연결할 때 최근 28일까지만 가져온다. 삼성 헬스에서 운동을 지워도 서버 값은 남는다(지우는 레코드 없음).
- 운동 부하는 저장 시점의 HRmax·RHR로 계산하며 이후 RHR이 바뀌어도 다시 계산하지 않는다. 종료 후 분석 뒤 늦게 도착한 W07 배치는 분석을 다시 실행하지 않으므로 그 러닝 부하에도 반영되지 않는다.
- 재평가 범위는 RHR·수면 변경은 이후 7일(RHR의 평소 값 창), 부하 변경은 이후 27일(부하 28일 창)이다. 다만 이력 일수 H는 창 밖의 첫 부하 날짜에도 달라지므로, 회원의 가장 오래된 부하가 지워지거나(러닝 삭제) 더 이른 부하가 늦게 들어오면 그 날짜+27일보다 뒤의 준비도 점수는 다시 평가되지 않는다. 그 날짜들은 다음 건강값 변경 때 갱신된다.
- Zone 경계는 기록 통계(H06)의 Karvonen 헬퍼를 그대로 쓰며, 부동소수 계산으로 경계와 정확히 같은 bpm이 한 단계 아래 Zone으로 분류될 수 있다(예: HRmax 190·RHR 없음에서 114bpm이 Zone1). 영향은 경계 1bpm이며 헬퍼(BE-C 담당) 변경은 이번 범위에 넣지 않았다.
- 수면·RHR 없이 부하만으로 계산된 준비도는 그 러닝을 삭제해 부하가 사라지면 계산할 항목이 없어져 이전 결과가 그대로 남는다(7.3 "계산된 항목이 없으면 기존 결과를 그대로 둔다"). RunWay 러닝만 있는 회원도 부하 항목만으로 준비도(신뢰도 LOW)가 생긴다.
