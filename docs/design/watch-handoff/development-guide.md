# RunWay 워치 UI 개발 지침

> 원본 핸드오프의 `CLAUDE.md`를 옮긴 문서다. 도구별 지시 파일로 자동 로드되지 않게 이름을 바꿨으며, 저장소 루트 `AGENTS.md`와 요구사항·API 문서가 이 지침보다 우선한다.

이 폴더는 RunWay 워치 앱 러닝 화면의 **디자인 핸드오프**다. 기준 시안은 **Rajdhani 버전**이다:
숫자 Rajdhani, 테두리 게이지 단색 블루 #4DC4FF, 핵심 숫자와 주 버튼 민트 #4DFFD2.
목표는 이 시안을 실제 워치 앱 UI로 구현하는 것이다.

## 먼저 읽을 것 (순서대로)
1. `spec/tokens.md` · `spec/tokens.json` — 색, 글꼴, 글자 크기, 부품 좌표
2. `spec/flows.md` — 개인·그룹 페이지 연결, 규칙, 상태 전이표
3. `spec/screens.md` · `spec/screens.json` — 화면 53개의 목적, 상태, 확인 필요 항목. 각 화면 이미지는 `screens/*.png`
4. `spec/unconfirmed.md` — 확인되지 않은 계약·정책, 디자인 잔여 문제, 접근성 메모
5. `spec/requirements-brief.md` — 기능 수정 요구사항 원문(참고)
6. 화면을 눈으로 확인할 때: `screens.html`을 브라우저로 연다(케이스 목업 포함 정적 렌더)

`design-source/`는 디자인 캔버스 원본(.dc.html)이다. 좌표·크기를 정확히 확인할 때만 참고한다. 코드로 그대로 옮기지 않는다.

## 대상 플랫폼 (작업 시작 전에 확인할 것)
- 요구사항 문서에는 서비스 코드 경로로 `wear/app/src/main/java/com/runway/watch/ui/`, `run/RunModel.kt`, `run/RunResult.kt`, `session/WatchSessionController.kt`, `navigation/WatchNavigation.kt`가 나온다.
  그래서 **Wear OS + Kotlin + Jetpack Compose for Wear OS**로 가정한다. 실제 저장소 구조를 먼저 확인하고 그에 맞춘다.
- 기존 코드의 상태 모델(예: RunModel, WatchSessionController)이 있으면 그것을 따른다. 새 상태 이름이나 필드를 임의로 만들지 않는다.

## 반드시 지킬 것
- **API·서버 필드·정책을 발명하지 않는다.** `spec/unconfirmed.md`의 '확인 필요' 항목은 TODO 주석과 함께 비워 두거나 기존 계약에 맞춘다.
  예: SET_BPM 범위, 자동 코칭 복귀, 끊김 중 제어, S08 휴대폰 인계 진입, 미확인 판정 시간, 그룹 종료 시 내 측정 자동 중지, 위치 없이 시작, 저장 2분 기준 시점.
- **확인 전에는 다음 상태로 표시하지 않는다.** 요청 → 기기 실행 확인 → 서버 저장 → 분석은 각각 별개다.
  예: '일시정지됨'은 기기 정지가 확인된 뒤에만, 목표 달성 배지는 서버 `goalAchieved` 기준으로만 표시한다.
- **연결 문제만으로 종료·유실·저장 성공을 단정하지 않는다.** "즉시 강제 종료" 같은 동작은 없다.
- **화면의 숫자는 모두 목업이다.** 실제 데이터 바인딩으로 바꾼다.
- 색 사용 규칙(`spec/tokens.md`)을 지킨다.
  - 민트: 핵심 숫자 1개와 하단 주 버튼에만
  - 블루: 테두리 게이지에만
  - 핑크: 경고·취소·하트에만
  - 상태는 색만이 아니라 아이콘·문구를 함께 써서 구분한다.

## 탐색
- 러닝 중 쪽 넘김은 HorizontalPager로 한다.
  - 개인: 운동 현황 → 페이스 코칭 → 기록 비교. 비교 기록이 없으면 2쪽.
  - 그룹: 운동 현황 → 공동 페이스 → 진행 순서·간격.
  - 개인↔그룹 사이에 없는 쪽으로 이동하지 않게 한다.
- 지표 상세(9.2-1~4)와 직접 조절(9.5b)은 별도 화면이다. 뒤로 가기로 원래 쪽에 돌아간다.
- 강제 전환은 세 경우에만 전체 화면으로 한다: 사용자 요청 결과(정지·재개·종료 확정/미확인), 휴대폰 인계 완료, 그룹 전체 종료 알림. 코칭 수신·연결 문제는 보던 쪽을 유지한다.
- 시스템 뒤로 가기·스와이프로 재개·종료하지 않는다. 종료 확인 화면에서 뒤로 가기는 '취소'다.

## 크기·접근성
- 시안은 454px 원형 = 227dp(1dp = 2px) 기준이다. 구현은 dp/sp와 비율로 하고 192dp·큰 글자에서 확인한다.
  시안의 고정 배치로는 넘치는 화면이 있다(`spec/unconfirmed.md` 잔여 문제).
- 터치 영역은 최소 48dp다. 원형으로 잘리는 가장자리 버튼은 실제 눌리는 영역을 확인한다.
- TalkBack 읽기 순서: 상태 → 핵심 수치(이름·단위 포함) → 보조 수치 → 쪽 위치 → 주 버튼 → 손잡이.
- 측면 버튼·회전 입력을 앱이 점유한다고 가정하지 않는다.

## 완료 확인
- 53개 화면이 `screens/*.png`와 같은 정보·위계·색 규칙으로 나오는지 확인한다(픽셀 일치까지는 요구하지 않음).
- `spec/flows.md` 상태 전이표의 각 전이가 동작하는지 확인한다. 특히 요청 중 잠금, 미확인 처리, 재개 후 마지막 쪽 복귀.
- 확인 필요 항목은 TODO로 남기고, 무엇이 미확인인지 보고한다.
