## 맥락

경로 재생(4.5 러닝 결과, 5.1 기록 카드, 2.1 분석, 7.2 커뮤니티 코스)의 공유는 지금까지 텍스트만 보냈다. 작업 요청자는 아래 세 가지를 요청했다.

- 지도 사진과 링크를 함께 보낸다.
- 받은 사람이 링크를 누르면 앱에서 그 러닝의 경로 재생이 열린다.
- 앱이 없는 사람은 웹에서 지도로 재생을 본다.

제약은 다음과 같다.

- **링크 형식:** 앱에 화면 이동용 링크가 없다. 사용자 정의 스킴은 `runway://spotify-callback` 하나뿐이다(ADR-0021). 카카오톡 같은 메신저는 `runway://` 주소를 누를 수 있는 링크로 보여 주지 않을 수 있다.
- **조회 권한:** 내 러닝 기록과 GPS 경로는 본인만 조회한다(H02·S11). 기록별 공개 설정은 없다. 게시물은 계정 공개 범위(공개 계정·승인된 팔로워)로 노출이 정해진다.
- **서명:** 폰 APK는 debug·release 모두 저장소의 팀 테스트 서명(`frontend/android/app/debug.keystore`)을 쓴다.

## 결정

1. **링크 형식** (가정)
   - 공유 링크는 서비스 도메인의 https 주소로 한다.
     - 내 기록: `https://k15e105.p.ssafy.io/r/{token}`
     - 게시물: `https://k15e105.p.ssafy.io/p/{postId}`
   - Android는 `MainActivity`에 `autoVerify` App Links intent-filter(`https`, 해당 호스트, `/r/`·`/p/`)를 둔다. 서버는 `/.well-known/assetlinks.json`을 제공한다.
   - 사용자 정의 스킴 링크는 만들지 않는다. https만 쓰므로 Spotify 콜백 필터와 겹치지 않는다.
2. **기록 공유 토큰** (가정)
   - 본인 기록을 공유할 때 서버가 기록마다 하나의 토큰을 발급한다. 토큰은 32바이트 난수를 base64url로 바꾼 43자이고, 평문으로 저장해 같은 기록이면 같은 링크를 준다.
   - 토큰을 가진 사람은 **로그인 없이** 그 기록 하나의 표시용 요약과 경로만 읽는다. 심박·목표·기기·세션 ID는 주지 않는다.
   - 기록이 삭제됐거나 발급자가 탈퇴했으면 404로 닫힌다.
   - 공유 취소 수단은 후속 업무로 미룬다.
3. **게시물 링크** (가정): 토큰 없이 게시물 ID를 쓰고, 기존 게시물 권한(로그인, 계정 공개 범위)을 그대로 따른다. 비로그인이면 앱이 로그인 뒤에 연다.
4. **웹 화면** (가정)
   - 앱이 없으면 `share.html`이 열린다. `/r/`이면 공유 기록을 읽어 네이버 지도 JS v3(Web Dynamic Map)로 재생한다(ADR-0018과 같은 지도).
   - `/p/`는 로그인이 필요해서 앱 설치·열기만 안내한다.
   - 웹 지도 키는 앱과 같은 Maps Application의 클라이언트 ID다. 배포할 때 주입하고 저장소에는 두지 않는다.
5. **사진** (가정)
   - 앱은 공유를 누르면 재생을 끝 상태(전체 경로가 그려진 개요 지도)로 넘긴 뒤 화면을 캡처하고, `react-native-share`로 사진과 링크 문구를 함께 보낸다.
   - Android 14 이상은 앱 네이티브 모듈(`ScreenCaptureModule`)이 PixelCopy로 재생 창의 화면 그대로를 복사한다. `react-native-view-shot`은 TextureView 지도를 글자 위에 덮고 경로가 빠진 프레임을 넣어서, 그보다 낮은 버전과 iOS의 대체 경로로만 쓴다.
   - 재생 지도만 TextureView로 그린다. SurfaceView는 캡처하면 검게 나온다.
   - 캡처·이미지 공유에 실패하면 텍스트(+링크) 공유로 돌아간다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. https App Links + 기록별 토큰 (선택) | 메신저에서 링크로 보인다. 앱이 없으면 웹으로 이어진다. 공유한 기록 하나만 열린다 | 비로그인 공개 API와 DB 테이블이 늘어난다. 서명 키가 바뀌면 assetlinks를 갱신해야 한다 |
| B. `runway://` 사용자 정의 스킴 | 서버·도메인 설정이 필요 없다 | 메신저에서 눌리지 않을 수 있다. 앱이 없으면 아무것도 열리지 않는다 |
| C. 기록 ID 링크 + 계정 공개 범위로 열람 | 토큰이 필요 없다 | 기록 ID만 알면 그 사람의 모든 기록을 볼 수 있어 공개 범위가 넓어진다. 비로그인 열람이 안 된다 |
| D. 웹 지도 Leaflet + OSM 공개 타일 | 키·요금이 없다 | 앱과 지도 모양이 다르다. 공개 타일은 저트래픽만 허용한다 |

## 결과

- **얻는 것:** 사진과 링크를 메신저로 보내 앱 또는 웹에서 같은 경로 재생을 본다. 공유하지 않은 기록은 여전히 본인만 본다.
- **감수하는 것:**
  - 링크를 가진 누구나 그 기록의 경로를 볼 수 있다. 출발점처럼 민감한 위치가 포함될 수 있다.
  - 취소 수단이 생기기 전까지는 기록 삭제로만 막을 수 있다.
  - 토큰은 접근 로그에서 지운다. 공유 페이지는 접근 로그를 남기지 않고, H09는 고정 경로로 기록하며, 공유 페이지의 Referrer-Policy는 `strict-origin`이다. 다만 백엔드 연결 실패 같은 Nginx 오류 로그에는 요청 경로가 남을 수 있다.
  - Web Dynamic Map은 이용 횟수 과금이다. 대표 계정은 월 600만 건까지 무료이고, 넘으면 0.1원/건이다.
  - assetlinks의 SHA-256은 팀 테스트 서명에 묶여 있다. 이 서명은 React Native 템플릿의 공개 debug 키다. 누군가 같은 패키지 이름·키로 만든 앱을 RunWay 대신 설치한 기기에서는 `/r/` 링크(토큰)가 그 앱으로 넘어갈 수 있다. 직접 설치를 거쳐야 하는 공격이라 작업 요청자가 위험을 받아들였다(2026-11-12, 리뷰 A-4·B-7).
- **후속 작업:**
  - 공유 링크 취소 API·화면
  - 폰·워치 공통 팀 전용 서명 키로 교체하고 assetlinks 갱신
  - iOS Universal Links (iOS 빌드 검증 시)
  - 팀 합의 후 채택으로 전환
