## 실행 순서와 증거

각 실행은 서로 다른 run ID로 구분한다. 실행 전후 앱 버전·APK 해시·targetSdk·기기 모델/API·센서 서비스 버전·권한·화면/AOD·절전·연결·충전 상태를 기록한다. 사용자 착용·행동 표시는 관찰 조건이며 독립 휴식 판정이 아니다.

### 1. IBI 품질과 배치 의미

먼저 기존 계측의 부족한 항목을 진단 앱에 추가하고 합성 입력으로 검사한다. 제품 코드는 변경하지 않는다.

- HR 상태 분포, IBI 정상/오류/값 이상/상태 누락/배열 불일치 집계와 분류 합계를 대조한다.
- 화면 꺼짐 배치에서 첫 포인트의 IBI 목록만 해당 목록으로 집계하며 후행 null을 오류나 목록 복제로 취급하지 않는다.
- 같은 포인트의 HR 상태 × 포함된 IBI 상태 교차 집계와 배치 전체 HR 상태 분포를 구분한다. 첫 포인트의 HR 상태를 배치 내 모든 박동의 동시 HR 상태라고 해석하지 않는다.
- 정상·양수 IBI의 목록 내 연속 개수와 간격 합계, 불량·미상으로 끊기는 횟수를 집계한다. 원시값은 메모리에서만 처리하고 출력·저장하지 않는다.
- 목록 내부 순서와 배치 간 인접성이 확인되기 전에는 서로 다른 배치의 정상값을 이어 붙이지 않는다. 목록 내 연속 길이와 실제 연속 측정 시간은 구분한다.
- SDK 시각의 기준, 목록 순서와 개별 박동 시각을 확인할 수 없으면 검증 불가로 남긴다. 배치 대표 시각을 모든 IBI에 복사하거나 HRV 값을 생성하지 않는다.

실기기에서는 초기 수신 점검 후 안정 자세·화면 켜짐과 안정 자세·화면 꺼짐을 분리한다. 화면 꺼짐은 우선 15분 관찰하되 자연 배치 확인 전 종료됐다면 수신 실패로 단정하지 않는다. flush는 별도 진단으로만 시행하고 횟수를 기록한다. 동일 조건을 반복해 구간별 정상 비율과 유효 연속 길이의 재현성을 비교한다. 실행 길이·순서는 기기 연결 후 사용자 착용 가능 시간에 맞춰 기록한다.

### 3. 실제 배치 전달과 배포 조건

송신 시도·수신 저장·ACK를 구분하고, 배치 ID별 최초 수신·중복·재시도·순서·누락과 중단 복구를 대조한다. 건강 원본을 AI 컨텍스트·로그·Jira로 가져오지 않는다. 필요한 실제 배치 처리는 기기 내부에서 수행하고 외부에는 집계 결과만 회수한다. 합성 전송 성공은 실제 건강 배치 검증을 대체하지 않는다.

제품의 서로 다른 패키지와 서명 조건, SDK 파트너 등록·배포 제한을 조사한다. 공통 식별자·통신을 바꿔야 하는 경우 검증 결과에 제약과 대안을 남기며, [ADR 운영 규칙](../adr/README.md)에 따른 별도 합의 전에는 제품 설정을 수정하지 않는다.

### 4. 통제된 배터리 비교

기존 배터리 도구는 OFF → HR → HR+가속도 순서의 20분 구간 또는 HR+가속도 단독 약 60분 관찰을 지원한다. 고정된 순서·짧은 구간·통제되지 않은 활동으로 얻은 결과는 제품 허용 예산의 근거로 바로 사용하지 않는다.

측정안은 **각 모드 60분 이상, 최소 2회 반복**으로 시작한다. 이는 계측 계획이며 확정된 제품 합격 기준이 아니다. 잔량 변화가 너무 작아 비교할 수 없으면 구간을 늘리거나 판정을 유보한다. 반복 간 모드 순서를 바꿔 잔량·시간대의 영향을 줄인다.

63번 제목은 “[워치] 별도 조작 없이 일상 심박 자동 수집·확인”이며 본문·완료 조건을 함께 변경했다. HRV(RMSSD·SDNN)의 수집·계산·저장·표시와 IBI 수집을 이번 Story에서 제외한다. 개별 박동 시각·배치 간 연속 IBI 증명은 HR 전용 기능의 착수 조건에서 빠진다. HRV 재도입은 별도 요구사항·검증·승인을 거친다.

63번의 HR 전용 구현은 계획·착수할 수 있다. 남은 항목은 이미 해결된 것으로 간주하지 않고 다음 구현 및 완료·제품 기본 활성화 전 검증 조건으로 넘긴다.

- 최초 동의와 켜기/끄기, 비러닝 자동 HR 수집, 착용·센서 품질·권한·미수신 상태 처리. 부족한 입력을 임의 값으로 채우지 않고 비러닝을 휴식/수면으로 단정하지 않는다.
- 제품 targetSdk/지원 OS의 권한 철회·재허용·화면 꺼짐·배경·프로세스 중단·재실행·재부팅 정책과 실기기 검증. 자동 재개와 명시적 재시작 조건을 구분한다.
- 기존 운동 수집과 일상 수집의 센서 소유권·등록/해제, 러닝 전환 시 중복·공백 검증.
- 173번 MessageClient 계약에 맞춘 실제 HR 배치·ACK 단계·재전송·중복/충돌·순서·중단/연결 복구 위험과 제품 package/서명 적합성. 장기 backlog 등 MVP 제외 범위를 추가하지 않는다. 서버 업로드는 63번 범위에 추가하지 않는다.
- 화면·통신·활동·온도를 통제한 HR 수집 배터리 비교와 제품 기본 활성화 전 허용 예산 합의. 이번 6시간 결과로 무영향·하루 수명·안전성을 선언하지 않는다.
- 선택한 수집 경로에 필요한 Samsung 제품 등록·스토어 서명·파트너/배포 적합성 근거 확보.

심박은 bpm·실제 측정 시각·워치 출처·수집/동기화 상태와 함께 표시하며 삼성 헬스 공식 일일 안정 시 심박으로 표시하지 않는다. 기존 60번 조회·53번 운동 수집 책임을 유지하고 기존 API·데이터 모델·공통 식별자/통신 규약 변경을 이 승인만으로 실행하지 않는다. 제품 기능 구현·서버 업로드·의료 정확도·SDK 내부 원인 완전 규명은 120번 종료 조건에 추가하지 않는다.
