## ERD 응답 대응 기준

**응답 해석:** 각 Response의 JSON은 기존 동작과 기능상 필요한 출력을 설명하는 검토용 예시다. 저장·전송 정책이 미정인 보완 필드는 구현 완료 계약을 뜻하지 않는다. 확인 필요 필드의 생략은 기능 삭제나 최종 선택 필드 확정을 뜻하지 않는다. `O`는 해당 응답 객체가 존재할 때 키를 포함함을 뜻하며, 값의 NULL 허용은 타입의 ` / null`로 구분한다. 조회 결과 자체가 없는 경우와 복구 행동은 해당 오류 응답 절을 따른다.

user_devices는 기기 연결, daily_health_metrics는 날짜별 건강 요약, sync_batches는 수신 배치다. 서버 BIGINT ID와 설치·클라이언트 배치·원본 측정 식별자는 서로 다르다. daily_health_metrics의 수면(분)·안정시 심박·운동부하·최대 심박은 모두 NULL 가능하다. 원본 워치 업로드 계약은 이 문서의 DB 식별자로 치환하지 않는다.

자료형·NULL의 정본은 [schema.sql](../db/schema.sql), 표시·관계 설명은 [ERD](../db/erd.md)를 따른다. ERD 정합성 단계에서는 API 종류·개수·역할·오류 응답을 유지했다. 후속 오류 검토 내용은 각 오류 응답 절을 따른다.

**사용 흐름과 응답 판단**

반환한 서버 기기 ID를 이후 업로드/해제에 사용한다. installationId는 같은 등록의 대응값이며 현재 블루투스 연결 상태와 구분한다.

### 오류 응답

**상태: 오류 계약 초안.** 기존 오류 코드에 발생 조건을 보완했다. HTTP 상태·코드는 기존 제안을 유지하며, 추가 후보는 아래에 구분한다. 이 표만으로 미정 정책을 확정하지 않는다.

| HTTP·코드 | 오류 종류 | 발생 조건·주의사항 |
|---|---|---|
| `409 DEVICE_CONFLICT` | 기기 관계 | 등록하려는 설치/기기가 다른 계정 또는 기존 연결과 충돌함. 설치 식별자 저장·재등록 정책 확인 필요 |
| `401 UNAUTHORIZED` | 인증 | 인증이 필요한 요청에 토큰이 없거나 만료·위변조되어 사용자를 확인할 수 없음 |
| `403 FORBIDDEN` | 권한 | 인증된 사용자가 해당 자원·작업에 필요한 권한을 갖지 않음 |
| `400 VALIDATION_ERROR` | 입력 형식 | JSON 구문·필수 필드·자료형·날짜 형식 또는 Path 식별자 형식이 맞지 않음. 서버 BIGINT 식별자의 소수·UUID·범위 초과 포함 |

- 공통 입력·서버 장애와 재시도 판단은 [오류 분류와 재시도 기준](README.md#오류-분류와-재시도-기준)을 함께 적용한다.
- **중복·경합 점검:** 통신 시간초과는 저장 실패를 뜻하지 않는다. 동일 요청 재전송·다른 요청과의 충돌을 구분한다. 기존 멱등 처리 기준이 없는 경우 성공 재응답/409/재조회 선택은 확인 필요다.

### 처리 규칙

- 실제 블루투스 연결은 기기 앱에서 제어. 동일 설치 중복 등록 방지.
- 사용자 소유권·그룹 참가 권한·상태 전이·재요청 여부를 검증한다(적용 범위는 API별로 결정).
- 예시는 **명세 구조를 보여주는 가상 값**이며, 확정되지 않은 제한·동기화 주기·AI 호출 주기를 의미하지 않는다.

### 상태값

- 기기·동의·동기화별 상태를 구분한다. 기록 공개 범위 상태는 사용하지 않으며 세부 상태값은 계약 확정 시 정의한다.

### 미정 사항

- [ ] 푸시 토큰을 기기 등록과 분리한 별도 API로 둘지 여부
- [ ] 요청·응답의 세부 필드 타입, 허용 범위, nullable 규칙 및 실제 JSON 구조 검토
- [ ] HTTP 성공 코드 및 각 예외의 오류 코드 최종 확정
- [ ] 실시간 전달 채널, 선두 경로 기준 순위·동기화 처리 확정

**상태: 오류 계약 초안.** 기존 오류 코드에 발생 조건을 보완했다. HTTP 상태·코드는 기존 제안을 유지하며, 추가 후보는 아래에 구분한다. 이 표만으로 미정 정책을 확정하지 않는다.

| HTTP·코드 | 오류 종류 | 발생 조건·주의사항 |
|---|---|---|
| `403 CONSENT_REQUIRED` | 동의 | 요청에서 수집·이용하는 건강·위치 정보에 필요한 동의가 없음/철회됨 |
| `422 UNSUPPORTED_RECORD_TYPE` | 데이터 종류 | 현재 지원 계약으로 해석할 수 없는 건강 레코드 종류 |
| `401 UNAUTHORIZED` | 인증 | 인증이 필요한 요청에 토큰이 없거나 만료·위변조되어 사용자를 확인할 수 없음 |
| `403 FORBIDDEN` | 권한 | 인증된 사용자가 해당 자원·작업에 필요한 권한을 갖지 않음 |
| `400 VALIDATION_ERROR` | 입력 형식 | JSON 구문·필수 필드·자료형·날짜 형식 또는 Path 식별자 형식이 맞지 않음. 서버 BIGINT 식별자의 소수·UUID·범위 초과 포함 |

- 공통 입력·서버 장애와 재시도 판단은 [오류 분류와 재시도 기준](README.md#오류-분류와-재시도-기준)을 함께 적용한다.
- **중복·경합 점검:** 통신 시간초과는 저장 실패를 뜻하지 않는다. 동일 요청 재전송·다른 요청과의 충돌을 구분한다. 기존 멱등 처리 기준이 없는 경우 성공 재응답/409/재조회 선택은 확인 필요다.

### 처리 규칙

- 실행 주체는 휴대폰 앱의 서비스다. 삼성헬스의 기기 내 저장소에서 읽은 기록을 서버에 보내는 통신이므로 업로드 API가 필요하다. 서버 내부 예약 계산으로 대체하지 않는다.
- 데이터 갱신·앱 실행·백그라운드 동기화 등 구체적인 호출 시점은 OS 제약을 포함해 별도 확정하며 사용자 수동 동기화 버튼을 전제하지 않는다.

- 휴대폰 앱이 삼성헬스에서 읽은 기록을 서버에 자동 전송한다. 서버의 평가 실행 요청과 구분한다.
- 반영한 건강·활동 데이터 변경에 따라 준비도를 내부에서 자동 재평가한다.
- 직접 워치에서 수집한 값이 삼성헬스나 서버에 자동 반영된다고 가정하지 않는다. 지표별 SDK 가용성과 출처 매핑을 확인한다.
- 실시간 수집·W07과 중복되는 운동은 출처·원본 ID·시각 등 식별 규칙을 정해 중복 집계를 방지한다.

- 수면, 심박, 활동량과 이전 운동기록 수신. 상세 종류·매핑·동기화 시점 미정.
- 사용자 소유권·그룹 참가 권한·상태 전이·재요청 여부를 검증한다(적용 범위는 API별로 결정).
- 예시는 **명세 구조를 보여주는 가상 값**이며, 확정되지 않은 제한·동기화 주기·AI 호출 주기를 의미하지 않는다.

### 상태값

- 기기·동의·동기화별 상태를 구분한다. 기록 공개 범위 상태는 사용하지 않으며 세부 상태값은 계약 확정 시 정의한다.

- [ ] HTTP 성공 코드 및 각 예외의 오류 코드 최종 확정

**사용 흐름과 응답 판단**

발신자가 어떤 배치가 저장되었고 무엇을 보관·재전송할지 판단한다. 단순 수신 상태를 영속 저장 ACK로 취급하지 않는다.

위 보완 필드는 호출 목적상 필요한 출력이다. 저장 컬럼 부재는 출력 불필요의 근거가 아니다. 저장·전송 정책 미정 항목은 위 설명의 계약을 확정한 후 구현한다.

| 후보 | 발생 가능 상황 |
|---|---|
| `403 SESSION_FORBIDDEN` | 기기 소유자와 연결 세션 소유자가 일치하지 않음 |
| `403 CONSENT_REQUIRED` | 건강·위치 수집 동의가 철회되거나 없음 |

**응답·복구 행동과의 연결:** 응답 유실 시 원본을 보관하고 동일 배치 ID·동일 해시로 재전송한다. COMMITTED와 영속 반영 범위 확인 전 삭제하지 않는다. ACK 범위·부분 실패 계약 미확정은 구현 차단 사항이다.

### 처리 규칙

- 그룹 강제 종료 기준 시각 이전 측정값은 지연 동기화여도 기록에 반영한다. 이후 값은 해당 그룹런 기록에 합산하지 않는다. 전송 수신 시각이 아닌 측정·종료 기준 시각으로 구분하고 기기 시각 보정 계약은 별도 정의한다.

- 본인 기기와 세션 연결·현재 동의·측정 시각 및 이벤트 순서를 검증한다. 기기 관계와 이벤트 스키마의 세부 검증은 미정이다.
- 늦게 끝난 분석이 더 최근의 사용자 BPM 변경이나 코칭을 덮어쓰지 않도록 입력·결과의 적용 순서를 관리한다. 버전·시각 필드의 구체 계약은 미정이다.

- 실시간 측정값과 오프라인 저장 기록을 통합 수신한다. 운동 중에는 서비스가 수집한 데이터를 작은 배치로 계속 전송하고, 재연결 후에는 미전송 기록을 재전송한다.
- 전송 주기·배치 크기·기기와 휴대폰 중 서버 호출 주체는 미정이다. 사용자 버튼 없이 동작하지만 기기와 서버 사이의 API 계약은 필요하다.
- `items`에는 원본 측정 ID·세션·기기·출처·측정 시각·값·단위·품질을 보존한다. GPS 포인트와 운동 제어·BPM 적용 이력의 타입별 구조는 별도 확정한다.
- 진행 중인 세션의 현재 분석에 유효한 새 측정값에 대해서만 실시간 코칭·기록 비교·BPM 갱신을 실행한다. 일시정지 구간·종료된 세션·중복·과거 재전송 데이터는 새 실시간 코칭을 만들지 않고 필요한 기록 복구·재집계에 사용한다.

- 워치 저장 데이터와 오프라인 기록을 앱이 자동 전송·재전송한다. 실시간 수집과 저장 기록 재전송은 같은 측정 식별·중복 제거 규칙을 사용한다.
- 종료 후 지연 업로드도 기록 복구 대상으로 취급하며, 이미 종료된 상태를 다시 진행 중으로 되돌리지 않는다. 상세 수용 조건은 미정이다.
- 새 데이터로 기록·통계·준비도 등 필요한 결과를 갱신하되 지난 시점의 실시간 코칭을 재생하지 않는다.
- 운동 종료·강제 종료 상태와 기록의 동기화 완료를 구분한다. 스트림별 이벤트 스키마·원본 워치 계약 매핑은 별도 확정한다.

기기별 스트림의 마지막 연속 반영 위치 조회.

### 인증 및 권한

- 로그인 사용자 본인 또는 서비스 리소스 접근 권한 검사.
- 건강정보·실시간 위치·타인 기록 조회 시 동의 상태 및 공개 범위가 우선한다.

### Path Parameters

| 필드 | 타입 | 필수 | 설명 |
|---|---|:---:|---|
| `deviceId` | integer (int64) | O | ERD 및 화면 요구사항을 기준으로 확정 필요 |
| `streamKey` | string (제안) | O | 기기 내 데이터 스트림 구분 키 |

### Query Parameters

없음

### Request Body

없음


### Response

`200 OK (제안)`

```json
{
  "deviceId": 101,
  "streamKey": "running-metrics",
  "lastContiguousSequence": null
}
```

응답 필드 정의(저장 필드는 ERD ver.3에 대응, 파생·미정 값은 설명에 구분):

| 필드 | 타입 | 필수 | 설명 |
|---|---|:---:|---|
| `deviceId` | integer (int64) | O | 조회한 본인 기기. |
| `streamKey` | string | O | 조회한 스트림. |
| `lastContiguousSequence` | integer / null | O | 영속 반영 연속 위치. 스트림 경계·초기값 계약 미정. |
| `updatedAt` | string (ISO 8601) | X | 저장 컬럼과 직접 대응하지 않는 응답 값. 산출·표시 구조 확인 필요 (ERD만으로 응답 형식을 확정하지 않음.) |
| `missingRanges` | array (구간 객체 구조 확인 필요) | 조건부 | 서버가 판정한 누락 범위. 구조·범위 미정이면 완전 수신을 뜻하는 []로 임의 응답하지 않는다. |


**사용 흐름과 응답 판단**

기기·스트림별 영속 반영 위치를 확인하고 필요한 범위부터 업로드를 복구한다.

위 보완 필드는 호출 목적상 필요한 출력이다. 저장 컬럼 부재는 출력 불필요의 근거가 아니다. 저장·전송 정책 미정 항목은 위 설명의 계약을 확정한 후 구현한다.

### 오류 응답

**상태: 오류 계약 초안.** 기존 오류 코드에 발생 조건을 보완했다. HTTP 상태·코드는 기존 제안을 유지하며, 추가 후보는 아래에 구분한다. 이 표만으로 미정 정책을 확정하지 않는다.

| HTTP·코드 | 오류 종류 | 발생 조건·주의사항 |
|---|---|---|
| `404 DEVICE_NOT_FOUND` | 대상 없음 | 기기 등록 관계가 없음. 연결 해제 기기의 조회/재시도 정책은 확인 필요 |
| `401 UNAUTHORIZED` | 인증 | 인증이 필요한 요청에 토큰이 없거나 만료·위변조되어 사용자를 확인할 수 없음 |
| `403 FORBIDDEN` | 권한 | 인증된 사용자가 해당 자원·작업에 필요한 권한을 갖지 않음 |
| `400 VALIDATION_ERROR` | 입력 형식 | JSON 구문·필수 필드·자료형·날짜 형식 또는 Path 식별자 형식이 맞지 않음. 서버 BIGINT 식별자의 소수·UUID·범위 초과 포함 |

**추가 오류 후보 — HTTP·코드·판정 정책 확인 필요**

| 후보 | 발생 가능 상황 |
|---|---|
| `403 DEVICE_FORBIDDEN` | 타인 기기의 동기화 진행 조회 |
| `400 INVALID_STREAM` | 기기에 대응하지 않는 streamKey. 스트림 저장 계약 미정 |

- **대상 없음·접근 차단 점검:** 경로 대상의 부재/삭제, 본인 소유·역할·참가 자격 불충족을 구분한다. 위 표에 없는 경우 `404` 자원 없음 또는 `403` 접근 거부의 추가 매핑을 확인한다. 존재 은닉을 위한 403/404 선택·검사 순서는 미정이며 새 코드로 단정하지 않는다.

- 공통 입력·서버 장애와 재시도 판단은 [오류 분류와 재시도 기준](README.md#오류-분류와-재시도-기준)을 함께 적용한다.

**응답·복구 행동과의 연결:** 연속 위치가 없다는 null과 sequence=0을 구분한다. 조회 실패만으로 전체 스트림을 처음부터 재전송하지 않는다.

### 처리 규칙

- 기기별 스트림의 마지막 연속 반영 위치 조회.
- 사용자 소유권·그룹 참가 권한·상태 전이·재요청 여부를 검증한다(적용 범위는 API별로 결정).
- 예시는 **명세 구조를 보여주는 가상 값**이며, 확정되지 않은 제한·동기화 주기·AI 호출 주기를 의미하지 않는다.

### 상태값

- 기기·동의·동기화별 상태를 구분한다. 기록 공개 범위 상태는 사용하지 않으며 세부 상태값은 계약 확정 시 정의한다.
