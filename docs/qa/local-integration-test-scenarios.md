# RunWay 로컬 통합 테스트 시나리오 (QA)

| 항목 | 내용 |
| --- | --- |
| 목적 | 1차 MVP 기능을 2계정·(가능하면) 2워치 구성으로 통합 검증 |
| 환경 | 로컬 BE + Android 에뮬/실기 + (선택) Wear OS 에뮬/실물 |
| 기준 | `docs/design/requirements.md`, API 계약, 현재 구현 가능 범위 |
| 작성 관점 | 전문 QA — 정상·경계·권한·상태전이·이중계정 상호작용 |
| 상태 | 초안. 실행 결과·차단 사유는 실행 시 갱신 |

---

## 0. 전제·구성

### 0.1 계정·역할

| 코드 | 역할 | 용도 |
| --- | --- | --- |
| A | 본인 계정 (호스트/크루장) | 그룹런 생성·시작, 크루 운영, 개인 러닝 |
| B | 더미 계정 (멤버) | 가입 신청·그룹런 참가·대기방 준비·동시 러닝 |

비밀번호·토큰은 문서에 적지 않는다. 로컬 회원가입으로 준비한다.

### 0.2 디바이스 구성 (목표)

| 코드 | 소유 | 유형 | 비고 |
| --- | --- | --- | --- |
| P-A | A | PHONE | 에뮬 또는 실기 1 |
| P-B | B | PHONE | 에뮬 또는 실기 2 (또는 A 기기 로그아웃 후 전환 — 비권장) |
| W-A | A | WATCH | 가상/실물. 서버 W01 `WATCH` 등록 |
| W-B | B | WATCH | 가상/실물. **다른 계정**으로 W01 등록 |

서버 계약(W01): 회원별·유형별 연결 중 기기 **1대**. 설치 식별자 없음 → “가상 등록”은 **계정별로 `POST /devices { deviceType: WATCH }`** 하면 서버 관점에선 성립한다. 실블루투스·센서 스트림은 별개다.

### 0.3 기술 타당성 (선검증 필수 — TS-FEAS)

| ID | 검증 항목 | 기대 | 실패 시 영향 |
| --- | --- | --- | --- |
| TS-FEAS-01 | A로 W01 WATCH 등록 → W02에 1건 | 201/200, `deviceType=WATCH` | 워치 세션 제어 불가 |
| TS-FEAS-02 | B로 W01 WATCH 등록 (A와 동시 유지) | B 계정에만 WATCH 1건. A와 무관 | 2인 워치 시나리오 축소 |
| TS-FEAS-03 | Wear 에뮬 2대 동시 / 또는 실물+에뮬 | 각각 폰(또는 페어링 대상)과 통신 | 워치 UI·센서 TC 보류, 서버 등록만으로 대체 표기 |
| TS-FEAS-04 | 가상 워치에서 HR/GPS/배치(W07) 업로드 | 표본·배치 수신 | AI 코칭·준비도·기록 품질 TC 제한 |
| TS-FEAS-05 | 그룹런 대기방 입장 창(시작 30분 전) | `canEnterRoom` true | DB `scheduled_at` 조정 또는 오늘 일정 생성 |
| TS-FEAS-06 | C01 Route+DEM | `BACKEND_ROUTE_*`·DEM 설정 후 후보 반환 | 코스 추천 TC → Blocked / stub 금지(실연동 목표 시) |

**판정:** TS-FEAS 미통과 항목은 해당 워치/코스 TC를 `Blocked`로 두고, 폰+서버 API만으로 진행 가능한 범위를 명시한다.

### 0.4 환경 체크리스트 (테스트 시작 전)

- [ ] BE 기동, DB/Redis healthy
- [ ] FE `dataSource=api`, 에뮬→`10.0.2.2:8080`
- [ ] cleartext / adb PATH
- [ ] A·B 회원가입·온보딩(러닝 프로필) 완료
- [ ] (실연동 시) Route 기동 + DEM 경로
- [ ] TS-FEAS-01~02 통과

### 0.5 결함 등급

| 등급 | 정의 |
| --- | --- |
| S | 데이터 손실·잘못된 계정 간 노출·결제/동의 우회 |
| A | 핵심 플로우(가입·러닝 시작·그룹 시작·기록 저장) 불가 |
| B | 주요 기능 오동작, 우회 가능 |
| C | UI/카피/비기능 |

### 0.6 테스트 데이터 규칙

- 그룹런 `scheduled_at`은 **지금+10분~20분** (대기방 30분 창)
- 크루명·그룹런 제목에 `[QA]` 접두
- 실행 후 상태(RUNNING/CANCELLED)면 다음 TC 전 **리셋 또는 신규 생성**
