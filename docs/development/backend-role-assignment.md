# 백엔드 역할 분담

> 상태: 작성 틀만 준비 · 담당자·분담 범위 미확정

백엔드 도메인과 공통 기반의 담당 범위를 합의한 뒤 기록하는 문서다.
현재 표는 논의를 위한 목록이며, 담당 인원·이름·업무 배정이나 착수 순서를 확정하지 않는다.
아래 행을 그대로 사람별로 나눌 필요는 없으며 합의에 따라 묶거나 분리할 수 있다.

## 1. 도메인별 담당

현재 [API 명세](../design/api/README.md)의 분류를 목록으로 정리했다.
API 초안의 기능 범위·담당자·패키지 경계가 모두 확정됐다는 의미는 아니다.
담당자와 범위를 결정하면 관련 Jira를 연결한다.

| 도메인 | 범위 확인 문서 | 담당자 | 합의한 담당 범위·경계 | 관련 Jira |
| --- | --- | --- | --- | --- |
| 인증·사용자·러닝 프로필 | [API](../design/api/users.md) | 미정 | 미정 | 미정 |
| 워치·건강 데이터 | [API](../design/api/devices-health.md), [워치 업로드 계약](../design/api/wear-upload-api.md) | 미정 | 미정 | 미정 |
| 운동 준비도 | [API](../design/api/readiness.md) | 미정 | 미정 | 미정 |
| 러닝 코스 | [API](../design/api/courses.md) | 미정 | 미정 | 미정 |
| 러닝 세션 | [API](../design/api/sessions.md) | 미정 | 미정 | 미정 |
| AI 페이스·실시간 분석·BPM | [API](../design/api/pace-coaching.md) | 미정 | 미정 | 미정 |
| 러닝 기록·분석 | [API](../design/api/running-records.md) | 미정 | 미정 | 미정 |
| 그룹런 | [API](../design/api/group-runs.md) | 미정 | 미정 | 미정 |
| 크루 | [API](../design/api/crews.md) | 미정 | 미정 | 미정 |
| 커뮤니티 | [API](../design/api/community.md) | 미정 | 미정 | 미정 |

워치·모바일·AI와 연결되는 행은 백엔드 측 담당 범위를 뜻한다. 다른 영역의 구현 담당까지
이 표로 배정하지 않는다.

## 2. 공통 기반 담당

| 공통 영역 | 확인할 범위 | 담당자 | 관련 Jira |
| --- | --- | --- | --- |
| 프로젝트·빌드·검증 | Gradle, 공통 의존성, 포맷 검사, 테스트 실행 설정 | 미정 | 미정 |
| 공통 API 처리 | 응답·오류 규약, 예외 처리, 입력 검증 연결 | 미정 | 미정 |
| 인증·보안 기반 | 인증 처리, 공통 보안 설정, 공개 경로 관리 | 미정 | 미정 |
| DB·마이그레이션 기반 | DB 연결, JPA 공통 설정, Flyway 변경 파일 관리 | 미정 | 미정 |
| 실행 설정·배포 연계 | 환경변수, 실행 안내, CI·인프라 담당과의 연결 범위 | 미정 | 미정 |

메시지·캐시 등 아직 사용 여부가 정해지지 않은 기술은 실제 필요가 확인될 때 추가한다.

## 3. 역할 결정 시 기록할 내용

- 담당자와 해당 도메인의 구현·테스트 범위
- 다른 도메인이나 모바일·워치·AI·인프라와 연결되는 지점
- 공통 파일 변경 시 확인할 담당자와 변경 책임
- 필요한 선행 업무와 관련 Jira
- 합의 일자와 확인 근거

담당자가 미정이라고 누구나 임의 변경할 수 있는 것은 아니다. 실제 작업을 시작할 때 현재
Jira와 팀 합의로 담당 범위를 확인하고 이 문서와 충돌하면 먼저 정리한다.
리뷰 편성은 [백엔드 작업 지침](../../backend/AGENTS.md)을 따른다. 역할 문서를 만들었다는
이유로 새로운 필수 팀원 승인 절차를 추가하지 않는다.
