## 맥락

스키마 설계는 PostgreSQL·PostGIS를 대상으로 한다. 실제 ERD를 구현하기 전에 개발 PC와
DB 통합 테스트에서 같은 DB 기능을 사용할 기반이 필요하다. ERD는 변경 중이므로
이번 결정으로 도메인 테이블·컬럼·공간 매핑을 확정하지 않는다.

## 결정

로컬 개발과 Testcontainers 통합 테스트는 `postgis/postgis:17-3.6`을 사용한다.
개발 DB는 Docker Compose, 테스트 DB는 격리된 일회성 컨테이너로 실행한다.
운영 버전·배포 구성·운영 계정 정책은 이번 결정에 포함하지 않는다.

합의 근거: 초기 구성 계획과 PostgreSQL 17·PostGIS 3.6 조합을 제안한 뒤 사용자가
“응”으로 진행을 승인했다. 도구 선택 승인과 실행 검증 결과는 구분한다.

## 고려한 대안

| 대안 | 판단 |
| --- | --- |
| PostGIS 포함 PostgreSQL 이미지 | 설계 대상 DB와 공간 확장을 개발·테스트에서 함께 사용할 수 있어 선택 |
| 이미 정해진 팀 DB 버전에 맞추기 | 제안 당시 확인된 별도 런타임 버전이 없어 신규 조합을 승인받음 |

다른 메이저 버전과의 성능 비교는 수행하지 않았다. H2 등의 대체 DB가 공간 동작까지
동일하게 보장한다고 가정하지 않는다.

## 결과

- **얻는 것**: 개발·통합 테스트의 DB 계열·확장 통일, 개발자 DB와 테스트 데이터 분리.
- **감수하는 것**: Docker 실행·이미지 다운로드 필요. 태그의 패치 내용은 갱신될 수 있음.
- **후속 작업**: 연결·PostGIS 확장 검증은 초기 구성의 Testcontainers 통합 테스트에서 완료했다.
  Compose 개발 DB 기동·재기동 확인은 별도로 기록한다.
  ERD 확정 후 첫 마이그레이션과 Entity 매핑을 검증한다.
  운영 이미지 고정·권한·백업·업그레이드 절차는 배포 설계에서 정한다.
