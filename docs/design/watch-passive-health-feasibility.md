# 일상 심박·IBI 자동 수집 기술 검증 결과

관련 업무: [S15P31E105-62](https://ssafy.atlassian.net/browse/S15P31E105-62) · 후속 구현: [S15P31E105-63](https://ssafy.atlassian.net/browse/S15P31E105-63)

검증일: 2026-10-21(KST) · 검증 시작 기준: `origin/dev`의 `3b5841f`

## 결론

**Watch7에서 HR·IBI를 수집할 수 있으나, 안정 구간의 IBI 품질이 불안정해 일상 자동 수집·HRV 기능의 채택은 보류한다.** 62번은 수행한 탐색 시험과 보관 기록 분석의 결과 정리로 범위를 조정해 마무리한다. 기존 완료 조건 중 미실행 검증은 후속 Task [S15P31E105-120](https://ssafy.atlassian.net/browse/S15P31E105-120)로 이관하며, 제품 적용·63번 착수의 선행 조건이 충족된 것으로 처리하지 않는다.

| 판단 대상 | 결과 | 제품 적용의 남은 조건 |
| --- | --- | --- |
| Samsung Health Sensor SDK 기반 HR 수집 | 조건부 후보 | 제품 targetSdk의 권한·배경 실행·러닝 전환·배터리 예산 검증 |
| IBI 기반 휴식·HRV RMSSD | 채택 보류 | 안정 구간 품질, 유효 연속 구간과 개별 IBI 시각 의미 확인 |
| 워치→휴대폰 전달 | 소규모 경로 가능성 확인 | 제품 패키지·서명, 실제 건강 배치의 누락·순서·중단 복구 검증 |
| 배터리 | 탐색 측정만 확인 | 수집을 끈 기준 조건과 모드별 반복 비교 |
| 공개 배포 | 미확인 | 파트너 승인·제품 패키지 및 서명 등록 조건 확인 |

불량 IBI를 임의값으로 채우거나 오류 구간 양옆의 정상값을 이어 붙여 HRV를 계산하지 않는다. HR 수집 성공을 휴식 판정이나 IBI 정확성의 증거로 대체하지 않는다.

## 검증 환경과 SDK 조건

| 항목 | 조건 |
| --- | --- |
| 워치·휴대폰 | Galaxy Watch7 SM-L300/API34 · Galaxy S22 SM-S901N |
| SDK·서비스 | Samsung Health Sensor SDK 1.4.1 · Health Sensor Service 1.6.05.03 |

| 전달 시험 | 워치·휴대폰 동일 applicationId와 debug 서명 |
| 자료 보관 | 원시 HR·IBI·가속도 값은 저장·출력하지 않고 집계와 시각 메타데이터만 보관 |

제품 앱의 소스·패키지·의존성은 변경하지 않았다. 일회성 진단 앱의 결과가 제품 targetSdk 37이나 다른 기기에서의 동작·정확성을 입증하지는 않는다. AOD·절전·삼성 헬스 설정을 고정한 통제 시험은 수행하지 않았다.

Service 1.5.04.08에서는 `OLD_PLATFORM_VERSION` 오류로 연결되지 않았고, 1.6.05.03으로 업데이트한 뒤 연결됐다. 센서 서비스 개발자 모드 활성화 전에는 `SDK_POLICY_ERROR`·수신 0건이 발생했고 활성화 후 실수신을 확인했다. 연결·지원 capability·측정 정책 허용을 각각 확인해야 한다. 개발자 모드는 공개 배포 해법으로 채택하지 않는다. [SDK 호환 정보](https://developer.samsung.com/health/sensor/api-reference/overview-summary.html), [앱 검증 정책](https://developer.samsung.com/health/sensor/guide/app-verification.html)

HR 포인트 주기는 1Hz지만 IBI가 항상 초당 하나라는 뜻은 아니다. 화면 꺼짐 배치에서는 전체 IBI·상태 목록이 첫 포인트에 모이고 나머지는 null일 수 있다. 목록을 중복 복제하거나 후행 null을 오류 박동으로 집계하지 않는다. IBI는 ms 단위이며 값과 상태를 같은 인덱스로 대응한다. IBI 상태 0은 정상·-1은 오류인 반면 HR은 상태 1이 성공이다. [데이터 명세](https://developer.samsung.com/health/sensor/guide/data-specifications.html), [HR·IBI 상태 명세](https://developer.samsung.com/health/sensor/api-reference/com/samsung/android/service/health/tracking/data/ValueKey.HeartRateSet.html)

### IBI 품질 분석

저장된 비율의 직접적인 이유는 **SDK IBI 오류 표시(-1)**다. 모든 구간에서 오류 상태 개수와 제외 개수가 일치했고, 값 이상·상태 누락·배열 대응 실패에 의한 IBI 제외는 없었다. 전체 IBI·상태 분포·분류 합계 및 HR/가속도 배치 합계를 대조했다. 상태 0을 오류로 뒤집거나 후행 null을 오류 IBI로 세는 코드 경로는 발견하지 못했다. SDK 상태는 품질 표시이며 생리적 정상 범위·의료 정확도를 뜻하지 않는다.

| 분석 항목 | 확인 결과 | 해석 |
| --- | --- | --- |
| 미배정 표본 | 전체 실행의 IBI 12개, 그중 정상 8개 | 정상 8개를 모두 재안정에 보태도 16.61%, 12개 모두 정상으로 가정해도 17.22%. 제외한 경계 표본만으로 낮은 비율을 설명할 수 없음 |
| 수신 지속성 | HR 약 1.000Hz·가속도 24.983Hz. 중복·역순 타임스탬프 0개, 시계 변경 감지 없음 | 대규모 이벤트 수신 중단이 주원인이라는 증거 없음. 개별 박동 누락 없음의 보증은 아님 |
| 시각·배치 | HR 후보 시각 최대 전진 간격 2.32초, 배치 최대 측정 범위 93초 | 긴 수신 대기와 센서 미측정을 구분해야 함 |
| HR와 IBI 품질 | 재안정 HR 성공 357/363개(98.35%), 정상 IBI 82/534개(15.36%) | HR 성공으로 IBI 품질을 대체할 수 없음 |
| 평균 비교 | 걷기 HR 평균은 성공 포인트 170개, IBI 평균은 정상 간격 435개로 계산 | 다른 표본·필터·가중치이므로 두 평균의 역수 불일치 자체는 오류 증거가 아님 |

미배정 표본 계산은 제외 표본의 영향 상한이며, 이미 배정한 IBI의 모든 SDK 배치 의미 오류를 배제하는 증명은 아니다. 평균의 역수와 역수의 평균도 일반적으로 같지 않으므로 같은 박동을 대응하지 않은 두 평균으로 정확성을 판정하지 않는다.

**물리적 원인은 보관 자료로 식별할 수 없다.** 배치 기록에는 시각·포인트 수만 있고 HR 상태×IBI 상태 교차 집계와 개별 IBI 시각은 없다. 오류가 특정 HR 상태와 동시에 발생했는지, 특정 시점에 집중됐는지 복원할 수 없어 착용·광학 신호·SDK 내부 처리 중 하나로 단정하지 않는다. 같은 걷기 시험 반복보다 배치 단위 대응 정보가 먼저 필요하다.

### 독립 실행·배터리 탐색 측정

일상 활동 조건에서 HR+가속도를 동시에 수집했다. 화면 강제 켜짐·wake lock 없이 배터리·시간·수신 개수를 워치 내부에 저장했다. 배터리 10% 이하·충전·잔량 미확인·SDK 오류를 중단 조건으로 설정했다. 이는 시험 중단 조건이며 제품 배터리 합격 기준이 아니다.

| 항목 | 관측 결과 |
| --- | --- |
| 실제 측정 길이 | 3,780.432초, 약 63분 |
| 종료 | `complete`, 오류 없음, 서비스 종료 확인 |
| 배터리 | 56%→49%, 7%p 감소. 해당 구간 약 6.67%p/h |
| 수신 개수 | HR 3,703개·가속도 94,200개 |
| 충전·잔량 | 종료 시 충전 아님, 10% 중단 조건 미도달 |

idle 허용 비정확 알람으로 약 60분 종료 요청보다 약 3분 늦게 종료해 실제 시간을 집계했다. 이 실행은 IBI 품질·센서 공백을 집계하지 않았으며 수신 건수만으로 연속성을 보증하지 않는다. 통신·활동·진단 파일 쓰기가 포함된 단일 관측으로 센서만의 추가 소모·하루 배터리 수명을 추정하지 않는다. 기준 조건·HR 전용 조건과의 반복 비교는 미실행이다.

종료 결과는 워치에서 회수했고 이 실행의 휴대폰 보고서 수신 여부는 미확인이다. 별도 20.926초 기능 점검에서 집계 보고서의 휴대폰 저장을 확인했지만 장시간 전달·배터리 비교 근거로 대체하지 않는다.

| 시험 | 결과 |
| --- | --- |
| 미연결 중 합성 배치 저장 | 고유 배치 2개·ACK 0개 |
| 앱 강제 종료 후 명시적 재실행 | 워치의 합성 배치 2개 보존 |

전달 내용은 합성 표식·배치 ID·시도 식별자뿐이며 실제 건강 원본은 전송하지 않았다. `put_accepted`와 수신 완료 ACK를 구분했다. 강제 종료 후 자동 실행, 실제 건강 배치·대량·순서·수신 중 전원 종료·정확한 지연은 미검증이다. 연결 대상은 등록 정보와 NodeClient를 대조해 확인했다.

## 시각 진단의 제한

SDK `DataPoint.getTimestamp()`는 ms 단위지만 기준 시계가 명시돼 있지 않다. wall/elapsed 시계와의 근접성을 후보 정렬로 기록했다. HR 시각 후보가 수신보다 최대 342ms 앞선 사례도 있어 시계 일치를 보증하지 않는다. [DataPoint API](https://developer.samsung.com/health/sensor/api-reference/com/samsung/android/service/health/tracking/data/DataPoint.html)

구간을 넘는 배치·실행 전 시각·미상 기준·중복·역순 및 도착 시 이미 알려진 표시 경계의 2초 이내 후보는 미배정한다. 앞으로 생길 표시를 알 수 없으므로 이전 집계의 소급 재배정은 하지 않는다. 2초는 진단용 여유이며 제품 기준이 아니다. IBI를 개별 박동 시각으로 복원하거나 배치 시각을 모든 IBI에 복사하지 않는다.

최종 연속 실행은 HR 배치 741개·가속도 배치 92개, 실행 전 시각 후보 1개였다. HR 최신 후보 시각 도착 차이는 -342~698ms, 가속도는 29~93ms였다. 경계/미상 후보 배치 HR 13개·가속도 6개와 미배정 HR 13포인트·IBI 12개를 구분한다.

## 62번 완료 범위와 후속 검증

2026-10-23 범위 조정: 62번의 산출물은 SDK 접근·HR/IBI 수신과 품질, 착용·탈착·권한 철회, 소규모 합성 배치 전달·재연결 및 단일 배터리 탐색 측정의 결과와 한계를 기록한 본 보고서다. IBI 기반 HRV 채택 보류를 탐색 검증의 결론으로 남긴다.

기존 완료 조건의 러닝 시작/종료 전환, 통제된 배터리 반복 비교·허용 기준, 유효 연속 IBI·측정 구간 기준과 제품 환경 검증은 미완료 항목으로 유지하고 [S15P31E105-120](https://ssafy.atlassian.net/browse/S15P31E105-120)에서 추적한다. 미실행 항목을 통과로 바꾸지 않으며, 아래 미검증 표와 63번의 HRV 요구사항은 유지한다. 후속 검증을 바탕으로 채택 여부·품질·배터리·실행 정책을 결정하기 전에는 63번의 선행 조건이 충족되지 않는다.

## 미검증 범위와 63번 착수 조건

63번은 별도 조작 없는 HR·HRV 확인을 목표로 하며 유효 휴식 구간·IBI 기반 RMSSD·측정 시각·러닝/권한/재시작/연결 복구·배터리 기준을 포함한다. **HR 수집 성공만으로 현행 63번의 선행 조건을 충족했다고 보지 않는다.**

후속 진행안은 다음과 같으며 제품 범위·기술 규약을 확정한 결정은 아니다.

1. **HR 전용 우선 구현:** HRV를 분리하는 범위 축소안이다. 범위 조정 합의 전에는 63번 HRV 완료 조건을 제거하지 않는다. HR 전용도 제품 권한·러닝 전환·배경 실행·배터리 검증이 필요하다.
2. **IBI 추가 조사:** 원시값 대신 같은 배치의 HR 상태×IBI 상태 교차 집계·합계/분포·시각 범위를 추가한 제한된 조사로 설계한다. 현재 합계만으로 원인 완전 규명을 시도하지 않는다.
3. **통신·배포 조건:** 검토 시점 제품 applicationId는 워치 `com.runway.watchdemo`·모바일 `com.runway.health`로 다르다. Data Layer의 동일 패키지·서명 조건과 식별자 변경의 설치·데이터·SDK 등록 영향을 평가해야 한다. 공통 통신·식별자 채택 시 [ADR 운영 규칙](../adr/README.md)을 적용한다. [Data Layer 조건](https://developer.android.com/training/wearables/data/overview)

제품 `wear/`의 검토 시점 targetSdk는 37이며 임시 앱의 targetSdk 35 시험이 제품 권한 조건을 대체하지 않는다. HR·활동 권한과 health foreground service의 배경 시작 제한을 실기기에서 확인해야 한다. 러닝용 `RecordingService`를 상시 수집 서비스로 그대로 재사용하지 않는다. [Samsung 권한](https://developer.samsung.com/health/sensor/guide/permission-request.html), [Android 배경 권한](https://developer.android.com/health-and-fitness/health-services/permissions), [health foreground service](https://developer.android.com/develop/background-work/services/fgs/service-types#health)

HR 전용 축소안의 비교 후보는 Health Services `PassiveMonitoringClient`다. IBI 제공을 전제로 하지 않으며 기기의 HR capability와 재부팅 후 등록 복원을 검증해야 한다. Samsung Health Data SDK·Health Connect 조회와 러닝 `ExerciseClient`는 일상 IBI 수집 검증을 대신하지 않는다. [배경 모니터링](https://developer.android.com/health-and-fitness/health-services/monitor-background)

## 검증 자료와 확인 방법
