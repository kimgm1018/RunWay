# S15P31E105-53 워치 실험 앱 검증

담당자: 강현 · 검증 기준일: 2026-10-19

## 변경 범위

Galaxy Watch7의 BPM 안내·운동 측정·로컬 저장·JSON 추출·수동 전송을 검증했다. 기능과 실행 안내는 [워치 앱 문서](../README.md), 데이터 형식은 [업로드 API 명세](../../docs/design/api/wear-upload-api.md)를 따른다.

## 2026-10-20: device 타입 및 support enum 변경

- `device`를 `DeviceInfo` 모델로 변경했다. api는 정수, bootCount는 정수 또는 null, synthetic은 Boolean 또는 null이며 model·appVersion은 문자열이다. 신규 측정에서는 api와 synthetic이 채워지고, 정보 없는 과거 기록은 null로 보존한다.
- 새 저장·추출·전송 JSON은 schemaVersion 2다. 기존 v1 숫자·Boolean 문자열을 읽고 bootCount의 `"-1"`을 null로 변환한다. 기존 SQLite 기록을 다시 열고 전송 대상으로 확보·재추출하는 회귀 테스트로 ID·기기 정보·capabilities 보존을 확인했다. 기존 추출 파일은 자동 변경하지 않는다.
- 지원 상태 생성·해석·비교에는 `SupportStatus` enum을 사용한다. JSON에는 기존 supported / unsupported / permission_denied 문자열을 유지한다. SDK availability·quality 원본은 문자열로 보존하고, 알 수 없는 지원 상태는 미확인으로 취급한다.
- `:app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest` 통과. 단위 테스트 40개, 실패·오류 0개이며 lint·debug 앱 및 기기 테스트 APK 빌드가 성공했다. 기존 JDK·의존성 관련 경고는 남아 있다.
- 아래의 2026-10-19 에뮬레이터·실기기 검증과 구분한다. 이번 타입 변경 후 에뮬레이터 자동 테스트는 재실행하지 않았다. 구버전 앱으로의 다운그레이드 호환성은 제공하지 않는다.

### 타입 변경 후 실기기 추출 확인

- 2026-10-20(PC 기준), 사용자가 실제 워치 SM-L300에서 운동을 기록·종료·추출했다. ADB로 가져온 원본 JSON을 Git 제외 경로 `tmp/watch-records/`에 보관하여 확인했다.
- schemaVersion 2, api 34·bootCount 3은 JSON 정수, synthetic false는 JSON Boolean, model·appVersion은 문자열이었다. support는 기존 소문자 문자열 계약을 유지했다.
- 정상 종료(COMPLETED/user), 운동 시간 75.549초, 샘플 421개를 확인했다. 심박·속도·케이던스·구간 거리 각 75개, 구간·누적 걸음 수 및 누적 거리 각 36개, 추정 보폭 13개다.
- 전체 샘플의 구간·세션 경과시간·UTC 환산·구간 끝 목표 BPM 연결과 종료 UTC 계산에 불일치가 없었다. 추정 보폭 13개의 동일 구간 거리÷걸음 수 계산도 일치했다. 센서 절대 정확도나 실제 앱 수신 지연을 검증한 것은 아니다.
- 새 워치라 과거 기록이 없어 실기기 v1→v2 업데이트 호환은 미검증이다. 기록의 목표 BPM 이벤트는 120 한 개여서 이번 실기기 실행에 BPM 변경 검증은 포함되지 않았다.
- 첫 기록의 시작 시각은 `2025-08-11T20:45:54.772Z`(한국 시각 2025-08-12 05:45:54.772)로 PC 기준 검증일과 달랐다. 사용자가 워치의 자동 날짜·시간 설정을 껐다 켜서 동기화한 뒤 새 기록을 생성했다. 이전 추출 파일은 그대로 보존했다.
- 시각 동기화 후 새 기록은 한국 시각 `2026-10-20 09:40:03.890`~`09:40:58.730`, 정상 종료, 54.840초·346개 샘플이었다. v2 device 타입과 전체 샘플의 구간·UTC 환산·목표 BPM 연결, 추정 보폭 24개의 동일 구간 거리÷걸음 수 계산에 불일치가 없었다. 목표 BPM 이벤트는 120 한 개다. 별도 기준시계에 대한 밀리초 단위 시각 정확도나 수신 지연을 측정한 것은 아니다.

## 2026-10-19 자동 검증

`wear/`에서 다음 명령을 실행하여 통과했다.

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:connectedDebugAndroidTest :app:lintDebug :app:assembleDebug
```

| 구분 | 결과 | 검증 내용 |
| --- | --- | --- |
| JVM | 29개, 실패·오류 0 | BPM·원본 시각·보폭·JSON, SQLite 저장·복구·동시 접근, 종료 실패, 오디오 실패, 운동 소유권 복구, 업로드 응답·제한 시간·재시도 |
| Wear OS API37 에뮬레이터 | 4개, 실패·오류 0 | 아래 통합 흐름 1개 및 오류·권한·기록 참가자 UI 회귀 3개 |
| lintDebug | 통과 | 기존 의존성 업데이트·JDK 관련 경고는 남아 있음 |
| assembleDebug | 통과 | debug APK 생성 |

통합 흐름은 참가자 입력 → 프리셋 120 선택 → +5로 125 → -5로 120 → 160으로 기록 시작 → 운동 중 140으로 변경 → Activity 재생성 → 정상 종료 → JSON 추출 → 서버 주소 미설정 전송 실패 및 원본 보존이다. 주요 화면의 세로 스크롤 부재와 종료 버튼 표시도 확인한다.

SQLite 테스트는 Robolectric API34로 실행했다. 어댑터 테스트는 SDK 데이터와 제어 가능한 ExerciseClient 대역을 사용한다. 기기 흐름은 실제 에뮬레이터 Health Services의 합성 데이터를 사용하며 실측 센서 검증이 아니다. 통합 테스트의 텍스트 입력 결과는 대역이고, 에뮬레이터 시스템 입력기 실행·결과 반환·저장은 별도 수동 확인했다.

## 독립 리뷰와 반영

운동 제어·재생, 측정·저장 데이터, 화면·업로드를 세 개 독립 세션에서 검토했다. 아래 사항을 수정하고 관련 회귀 테스트와 재검토를 수행했다.

| 발견 사항 | 수정 | 근거·회귀 검증 |
| --- | --- | --- |
| DB 상태 저장 실패가 센서 정지를 건너뜀 | 저장·cue 정지·센서 정지를 분리하고 실패한 센서 정지를 정리 단계에서 재시도 | 상태 쓰기 실패 주입, 첫 정지 실패 후 재시도 |
| 오류 사유·권한·미지원 이유가 화면에 없음 | 실패 안내, 결측 이유, 상태·상세 화면 추가 | 오류 사유·심박 권한 안내 UI 테스트 |
| 이전 기록의 참가자 식별 불가 | 선택 영역에 날짜·참가자 ID, 상세에 전체 ID·종료 사유 표시 | 기록·전송 화면의 저장 참가자 확인 |
| 구간·누적 지표의 지원 키 충돌 | metric별 support/availability 키 추가, 기존 이름 읽기 호환 유지 | 구간만 지원하는 SDK 어댑터 조건에서 구간·누적 상태 분리 |
| 거리 구간 정확도 메타데이터 누락 | 구간 accuracy와 파생 보폭 원본 품질 보존 | 어댑터에서 JSON까지 정확도 문자열 보존 |
| 최초 지원 정보 수신 전 직접 보폭을 추정값이 덮을 수 있음 | 지원 정보를 먼저 전달하고 명확히 unsupported일 때만 추정 | 지원 정보 지연·직접 보폭 동시 입력 시 추정 덮어쓰기 방지 |
| 전송 상태 변경 후 데이터 읽기 실패로 UPLOADING 고착 | 상태 변경과 payload 읽기를 하나의 트랜잭션으로 처리 | 읽기 실패 시 PENDING 롤백, 실제 SQLite·로컬 HTTP 재시도 |

## 실기기와 추출 파일

- Galaxy Watch7의 기본 사용 흐름은 2026-10-19 강현이 실기기 검증 완료를 보고했다. 자동 검증과 별도의 사용자 확인 결과다.
- 실기기 추출 샘플 680개의 세션 경과시간·UTC·구간 끝 목표 BPM 연결과 종료 시각 계산에 불일치가 없었다. 최상위 15개, BPM 이벤트 5개, 샘플 10개 필드 구성을 당시 생성 코드와 대조했다.
- 해당 실험에서는 직접 보폭 지표가 미지원이었으며 보폭 29개는 거리÷걸음 수 추정값이었다. 모든 기기에 같은 지원 상태나 샘플 수를 보장하지 않는다.

검증 중 에뮬레이터 합성 센서 미수신으로 데이터 대기 테스트가 실패한 실행이 있었다. 가상 워치 재부팅 후 전체 테스트를 재실행하여 통과했다.
