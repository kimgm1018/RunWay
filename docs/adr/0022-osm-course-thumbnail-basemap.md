## 맥락

S15P31E105-562에서 저장한 코스·프로필 기록 카드의 썸네일을 네이버 지도(ADR-0018)로 바꿨다. 이후 다음 문제가 드러났다.

- **표기 의무:** 네이버 지도 SDK는 지도마다 NAVER 로고를 가리지 않고 보여야 한다. 작은 카드마다 로고가 들어가 디자인을 해친다.
- **성능:** 카드마다 네이티브 지도 뷰가 하나씩 생긴다. 에뮬레이터에서는 카드 여러 개의 지도 바탕이 불러와지지 않았다. ADR-0018은 지도 뷰 호출량 과금 가능성 때문에 화면마다 지도를 새로 만들지 말라고 적었다.
- **데이터 추출 금지:** 네이버 지도 데이터를 추출해 다시 그리는 방식은 약관상 쓰지 않는다.

처음에는 썸네일이 실제 장소의 길·강·바다·공원만 보여 주면 되고 건물·글자는 필요 없다고 봤다(아래 결정에서 건물을 넣기로 바꿨다. 글자는 여전히 넣지 않는다). 프로젝트에는 이미 전국 OSM 자료가 있다. Route 서비스(ADR-0019, S15P31E105-586·601)의 읽기 전용 마운트에 다음 두 가지가 들어 있다.

- 모든 highway way와 태그(`store/network`)
- 강·물·해안·해변·공원·녹지 레이어(`store/envcache/layers.gpkg`)

Jira 본문의 "S15P31E105-288 전국 OSM 러닝 도로망"은 저장소에서 이 전국 자료(586·601)로 이어진다.

OSM 데이터는 ODbL이다. OSMF Attribution Guidelines(2021-06 채택)는 지형지물이 100개 미만인 정적 이미지의 개별 표기를 면제한다. 다만 근거가 되는 Substantial Guideline은 이 면제를 "같은 프로젝트에서 반복하지 않는 1회 추출"로 한정한다. RunWay는 코스마다 추출하므로, 앱 전체 차원의 표기도 함께 둔다.

## 결정

2026-11-10 실기기 확인과 실제 OSM 비교 미리보기를 거쳐 작업 요청자가 "건물까지 그린 평면 지도, 썸네일에 OSM 표기"(비교 시안 ⑤)를 골랐다. 처음 제안(지형지물 99개 이하 벡터, 표기 없음)은 이 결정으로 바꿨다.

1. **데이터 출처와 조회** (가정)
   - 백엔드가 코스 저장 커밋 뒤 Route 내부 API `POST /internal/v1/basemaps`(`detail: "full"`)를 호출한다. 코스 경로가 아닌 범위(bbox)만 보낸다.
   - Route는 전국 OSM 자료에서 모든 도로·산책로(등급 `road_class`), 강·물·해안·해변·공원·녹지, 해안선으로 만든 바다 면, 그리고 **건물 윤곽**을 bbox로 잘라 돌려준다. 외부 인터넷과 추천 엔진 lock을 쓰지 않는다.
   - Route 메모리·CPU(1 CPU·2 GB)를 추천과 나눠 쓰므로 full 요청은 한 번에 1건만 처리하고, 기다려도 차례가 오지 않으면 503 `BUSY`로 거절한다. 건물은 투영 전에 남은 개수 예산만큼 큰 것부터 남긴다. 백엔드는 축척(`meters_per_pixel`)을 함께 보내고, Route는 그 축척에서 보이지 않는 보행로·이면도로·작은 건물을 읽은 직후 뺀다.
   - 건물은 Geofabrik 한국 OSM 추출본(ODbL)에서 `build_buildings.py`로 만든 `buildings/buildings.gpkg`를 전국 자료 마운트에 **추가**해 쓴다. 기존 `store/`는 바꾸지 않는다. 2026-11-10 운영 서버에 1,383,390동(OSM 2026-11-08)을 넣었다.
2. **그리기와 저장** (가정)
   - 지형지물이 수천 개라 앱이 벡터로 그리면 무겁다. 그래서 **백엔드가 Java2D로 600×900 PNG 한 장**(위에서 내려다본 지도 + G안 코스 선, 글자 없음)을 그려 이미지 볼륨([ADR-0016](0016-image-volume-storage.md))에 저장한다. 새 라이브러리는 쓰지 않는다.
   - 도로 선 굵기는 1 km 코스 기준 시안 굵기에 축척 비율을 곱해(하한 0.3배) 넓은 코스에서도 지도가 흰 면이 되지 않게 한다. 요청 범위가 상한(축마다 7.9 km)에 걸리면 카드에 보이는 부분 쪽으로 옮긴다.
   - 이미지는 F02로 토큰 없이 조회한다(공용 코스 그림, `course_basemaps`가 참조하는 키만). 키가 그릴 때마다 새 UUID라 이 이미지에만 장기 캐시(`public, max-age=31536000, immutable`)를 허용한다. 저장 경쟁에서 지거나 DB 저장에 실패하면 방금 쓴 PNG를 지운다.
   - `course_basemaps`(코스당 1행, 이미지 키, OSM 시점, 그리기 버전 `flat-v1`)에 기록하고 C03 `basemap.imageUrl`(`/api/v1/images/{id}`)로 내려준다. 앱은 그림을 카드에 깔고 오른쪽 위에 "© OpenStreetMap"을 표기한다.
3. **기존 코스** (가정): 서버 기동 시 Route 준비를 기다린 뒤, 썸네일이 없거나 그리기 버전이 다른 ACTIVE 코스를 일괄로 그린다. 일괄 작업 사이에는 간격(기본 2초)을 두고, 새로 저장한 코스를 먼저 처리하며, Route가 잠깐 멈춘 실패는 같은 실행 안에서 한 번 더 시도한다.
4. **장애 시 동작** (가정)

   | 상황 | 저장 | 앱 표시 | 재시도 |
   |---|---|---|---|
   | Route 지연·5xx·잘못된 응답, 그리기·저장 실패 | 저장하지 않음 | C03 `basemap: null`, 선 썸네일 | 일괄 채우기 중 일시 실패는 1분 뒤 1회, 그 밖에는 다음 기동 때 |
   | 전국 자료 범위 밖 | 그림 없이 행 저장 | 선 썸네일 | 하지 않음 |
   | 건물 자료 없음 | 건물 없이 그림 | 그림 | — |

   코스 저장 응답에는 영향이 없다.
5. **표기** (가정)
   - 지형지물이 100개를 넘으므로 썸네일에 "© OpenStreetMap"을 표기한다(앱이 그림 위에 표시).
   - 설정 > 데이터 라이선스에서 'Map data from OpenStreetMap'·openstreetmap.org/copyright 링크와 네이버 지도 SDK 법적 공지·오픈소스 라이선스(SDK의 `LegalNoticeActivity`·`OpenSourceLicenseActivity`, Android)를 제공한다.
6. 큰 화면(코스 러닝·기록 상세 등)의 지도는 ADR-0018대로 네이버 지도를 유지한다. 이 결정은 카드 썸네일에만 적용한다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. Route 내부 API로 전국 OSM 자료 재사용 (선택) | 이미 배포·검증된 자료를 쓴다. 외부 의존·요청 제한이 없다. 코스 생성과 같은 OSM 시점이다 | Route 내부 계약이 늘어난다(AI 영역 합의). 전국 자료 범위 밖은 비어 있다 |
| B. 백엔드가 공개 Overpass API 조회 | Route 변경이 없다. 최신 OSM을 쓴다 | 공용 서버 사용 정책·요청 제한·장애에 의존한다. 응답이 느리고 일정하지 않다. 일괄 채우기 때 부하가 몰린다 |
| C. 백엔드가 마운트된 `layers.gpkg`·npy 직접 읽기 | 네트워크 호출이 없다 | Java GeoPackage·JTS 의존성이 새로 필요하다. Route 자료 형식(npy)을 백엔드가 중복 해석한다 |
| F. 99개 이하 벡터를 앱이 그림(처음 제안) | 표기가 필요 없다. 서버 그리기가 없다 | 카드에 보이는 지형지물이 적어 실기기에서 밋밋했다. 건물을 넣을 수 없다 |
| G. 모든 지형지물·건물을 벡터로 내려 앱이 그림 | 앱에서 스타일을 바꾸기 쉽다 | 코스당 약 500 KB, 카드 1장에 3,500개 이상을 그려 목록 스크롤이 무겁다 |
| H. 3D(건물 높이·기울인 시점) PNG | 네이버 3D와 비슷하다 | 높이 정보가 있는 건물은 약 20%뿐이고 코스 모양이 납작해진다. 미리보기 후 평면을 골랐다 |
| D. 네이버 지도 썸네일 유지 | 지도 품질이 높다 | 카드마다 로고·네이티브 뷰·과금 문제가 남는다(562에서 확인) |
| E. 네이버 Static Map 이미지 | 이미지 한 장이라 가볍다 | 호출당 과금, 로고 표기 의무가 같다. 앱 디자인 색 지정이 제한된다 |

## 결과

- **얻는 것**
  - 카드 썸네일이 네이티브 지도 없이 이미지 한 장으로 가볍게 보이고, 건물까지 그려져 네이버 지도에 가까운 상세도를 얻는다.
  - 외부 지도 호출 비용이 없다.
- **감수하는 것**
  - OSM 국내 상세도(특히 건물)는 지역별 편차가 있다. 바다는 해안선이 범위를 가로지를 때만 채운다.
  - 썸네일에 OSM 표기가 들어간다.
  - Route 요청 범위가 축마다 8 km 이하라, 코스 폭이 약 2.7 km를 넘으면 카드 위아래에, 약 3.3 km를 넘으면 좌우에도 지도 없이 바탕색인 띠가 남는다(5 km 이상 코스는 가운데 7.9 km만 지도).
  - 전국·건물 자료를 갱신하거나 그리기 버전을 올리기 전까지 저장된 썸네일은 바뀌지 않는다. 다시 그리면 이전 PNG 파일은 볼륨에 남는다(저장 실패·경쟁에서 진 파일만 바로 지운다).
  - Route 내부 계약, 건물 자료 파일, `course_basemaps` 테이블, 이미지 조회 허용 범위가 늘어난다.
- **후속 작업**
  - 팀 확인 후 채택으로 바꾼다.
  - 전국·건물 자료 갱신 주기와 재생성 방법을 정한다. 지금은 `render_version`·OSM 시점으로 대상을 찾을 수 있게만 한다.
  - 다시 그린 뒤 남는 이전 PNG 정리 방법을 정한다.
  - 다른 사람의 자유 러닝 코스 저장([S15P31E105-616](https://ssafy.atlassian.net/browse/S15P31E105-616))이 같은 저장 이벤트를 발행하게 한다.
  - iOS 네이버 법적 공지 메뉴를 만든다.
  - 넓은 코스의 바탕색 띠: 배포 후 실제 코스 폭 분포(7.9 km 초과 비율)를 확인한다. 개선이 필요하면 넓은 범위에서 건물을 빼고 큰 도로·물·녹지만 그리는 축척 단계를 두어 Route 상한을 올리거나(부하 재측정 필요), 띠를 지도 가장자리와 이어지는 색으로 처리한다.
  - 기준 확인(2026-11-10): OSMF [Attribution Guidelines](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines)·[Substantial Guideline](https://osmfoundation.org/wiki/Community_Guidelines/Substantial_-_Guideline). 네이버 지도 Android SDK 3.23.2 AAR 매니페스트의 법적 공지 Activity 선언.
