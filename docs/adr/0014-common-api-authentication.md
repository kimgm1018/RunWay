# ADR-0014: 공통 회원 API는 짧은 Bearer JWT를 검증하고 문서 인증을 분리한다

| 항목 | 값 |
|---|---|
| 상태 | 채택 |
| 결정일 | 2026-10-27 |
| 결정자 | 작업 요청자(정책 선택 및 191번 플랜 승인) |
| 관련 | [S15P31E105-191](https://ssafy.atlassian.net/browse/S15P31E105-191), [공통 API 규약](../design/api/README.md), [인증 계약](../design/api/users.md) |
| 대체 관계 | 대체함: [ADR-0013](0013-jwt-authentication.md) |

저장소 후속 결정: [ADR-0015](0015-redis-refresh-token-store.md)에서 갱신 권한 저장소를 Redis로 구체화한다. 이 문서의 JWT·문서 인증 결정은 유지한다.

## 맥락

기존 크루·게시글·댓글 API는 클라이언트의 `X-User-Id`를 신뢰한다. 이를 서버가 검증한 사용자 식별로 바꾼다.
단일 Spring MVC 백엔드가 토큰을 발급·검증하고, 서버 한 대에서 서비스와 팀 API 문서를 제공한다.

ADR-0013은 로그아웃 뒤 JWT 잔여 접근을 허용하되 회원탈퇴는 별도로 취급했다. 작업 요청자는
2026-10-27 요청별 조회 비용을 이유로 탈퇴 후에도 기존 Access Token을 만료까지 최대 10분 허용한다고
명시했고, 공통 인증·문서 접근·이 후속 ADR을 포함한 191번 플랜을 승인했다. 기존 결정 본문은 보존한다.

## 결정

Spring Security의 JWT 발급·검증을 사용한다. 현재 발급·검증 주체가 한 백엔드이므로 HS256과
서버에서만 관리하는 최소 256비트 난수 키를 사용한다. 허용 알고리즘과 필수 claim을 고정하며
암호 연산을 직접 구현하지 않는다. 키는 환경별로 분리하고 소스·이미지·로그에 넣지 않는다.

- Access Token 최대 600초, 최초 로그인부터 갱신 권한 최대 30일을 승계한다. JWT는 로그인 절대 상한을 넘지 않게 발급하고 서버 시각이 exp 이상이면 거절한다.
- 회원 API는 `Authorization: Bearer`를 사용하고 검증한 sub로 사용자를 식별한다. X-User-Id, 본문 ID, 문서 인증을 회원 인증으로 신뢰하지 않는다.
- 로그아웃·탈퇴·향후 정지 후에도 기존 JWT는 원래 exp까지 인증에 사용할 수 있다. 즉시 차단용 요청별 로그인/계정 상태 조회나 Access Token 차단 목록은 도입하지 않는다.
- 자원 소유권·현재 동의·공개 범위·자원 존재 검사는 유지한다. 탈퇴 후 새 발급·갱신으로 접근을 연장하는 결정은 아니다. 동의 철회나 삭제된 자원 접근을 허용하는 결정도 아니다.
- Refresh Token의 최대 유지기간·해시 저장·회전·계열 폐기 계약은 승계하며 구현은 후속 업무에서 수행한다. 갱신 권한 폐기와 JWT 즉시 차단을 구분한다.
- 로컬 Swagger는 루프백 환경에서 사용한다. 공유 서버의 문서 화면·명세·관련 자원은 HTTPS 아래 별도 HTTP Basic 계정으로 보호하며 회원 API는 여전히 JWT를 요구한다.

claim·경로·응답 세부는 API 정본에, 변수와 실행 방법은 백엔드 README와 예시 설정에 둔다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| HS256 공통 검증 (선택) | 단일 서버의 키 운영이 단순하며 별도 인증 서비스 불필요 | 키를 가진 검증자는 발급도 가능. 키 유출 영향이 전체 JWT에 미침 |
| RS256 | 검증키와 서명키 분리에 유리 | 현재 별도 검증 서비스가 없어 추가 키 운영의 실익이 작음 |
| 요청별 계정·세션 상태 조회 | 즉시 접근 차단 가능 | 조회 비용·가용성 의존 증가. 사용자가 짧은 잔여 접근을 선택 |
| 문서 비활성화 또는 외부 공개 | 운영 설정이 단순 | 배포 API 확인 불편 또는 팀 문서 무제한 공개. 로컬 사용과 공유 서버 별도 인증을 선택 |

## 결과

- **얻는 것**: 공통 인증과 업무 권한 검사를 분리하고 기존 API의 사용자 가장 경로를 제거한다. 별도 개발 서버 없이 팀 문서를 사용할 수 있다.
- **감수하는 것**: 탈취되거나 탈퇴 전에 발급된 JWT의 잔여 접근 위험을 최대 10분 수용한다. 키 교체는 이전 토큰 검증 실패를 유발한다. 갱신 상태 관리는 여전히 필요하며 전체 시스템이 무상태인 것은 아니다. 문서 계정과 HTTPS 운영도 필요하다.
- **후속 작업**: 191번의 발급·검증·가장 방지·문서 인증 분리 테스트를 수행한다. 로그인·갱신·탈퇴의 새 발급 제한과 계열 폐기는 후속 업무에서 구현·검증한다. 현재 스키마에 없는 정지 상태는 이 결정만으로 추가하지 않는다.
- **재검토 조건**: 검증 서비스 분리, 즉시 차단 요구, 키·토큰 탈취 사고 발생 시 새 ADR로 변경한다.
