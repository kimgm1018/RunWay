# RunWay 워치 수정 프롬프트 — 기존 디자인·색상 그대로 유지

첨부한 `runway-watch-canvas-project.zip`을 검토하고, RunWay 서비스와 맞지 않는 동작·문구·상태·탐색 흐름만 수정해 줘.

**디자인과 색상은 첨부 ZIP의 원본 그대로 유지해 줘. 리디자인하지 마.** 이전에 제안된 네이비·화이트·민트 팔레트, `#A7F6EC` 적용, 앱 카드 스타일, 서체 교체 등의 제안은 이번 작업에 적용하지 마.

이번 작업은 디자인 산출물 안에서 기능 명세와 사용자 흐름을 바로잡는 작업이다. 실제 RunWay 서비스 소스 수정, 브랜치·worktree 생성, 커밋·푸시·MR·Jira 변경은 하지 마.

## 1. 최우선 조건: 원본 디자인·색상 보존

- 기준은 첨부 ZIP의 기존 디자인이다. 이전 수정 프롬프트나 별도 제안 이미지·HTML을 새로운 기준으로 사용하지 않는다.
- 기존 배경색, 강조색, 텍스트 색상, 상태 색상, 투명도와 그라데이션을 그대로 유지한다.
- 기존 서체, 숫자 스타일, 글자 굵기·크기, 아이콘, 버튼 모양, 테두리, 라운드, 그림자, 케이스 표현을 그대로 유지한다.
- 기존 화면 구성, 정보 배치, 여백, 링·게이지·눈금, 페이지 표시의 시각적 형태를 그대로 유지한다.
- Barlow 전환, 민트 `#A7F6EC` 적용, 팔레트 통일, 링 축소·삭제, 숫자 중심 레이아웃, 앱 카드 스타일로의 재구성은 하지 않는다.
- 원본의 기존 색을 새 색으로 치환하지 않는다. README·토큰·공통 컴포넌트의 색상 기본값도 변경하지 않는다.
- 새 기능·누락 상태를 표현해야 할 때는 기존 부품과 스타일을 재사용한다. 기존 화면 전체를 다시 배치하지 않는다.
- 필요한 문구 수정과 조건별 표시, 상태 연결, 페이지 진입 조건, 보이지 않는 터치 영역 개선을 중심으로 작업한다.
- 기능 문제를 해결하려면 기존 배치·크기·게이지 구조를 바꿔야만 하는 경우, 임의로 바꾸지 말고 별도의 ‘디자인 변경이 필요한 잔여 문제’에 이유와 최소 변경안을 기록한다. 해당 변경은 기본 산출물에 적용하지 않는다.
- 기능 수정에 필수적인 제어·상태를 추가한 부분은 변경 목록에 명시하고, 원본 스타일을 따랐는지 설명한다.

원본 화면이 수정 후에도 같은 디자인으로 보이는 것이 핵심 조건이다.

## 2. 입력과 범위

- 입력 ZIP: `runway-watch-canvas-project.zip`.
- 로컬 입력 경로: 작성자 로컬의 캔버스 프로젝트 ZIP(개인 경로 생략).
- 서비스 저장소를 읽을 수 있다면: RunWay 서비스 저장소(이 저장소, 개인 경로 생략).
- 이전 검토의 원격 dev 기준: `fe1e931f35646dc85622b999e51f5f19962082c5` (2026-11-08). 저장소 접근이 가능하면 작업 시점의 최신 dev와 대조하되 원본 저장소 상태를 변경하지 않는다.
- 저장소를 확인할 수 없다면 아래 계약 사항을 검토 기준으로 사용하고, 현재 구현을 직접 확인한 것처럼 보고하지 않는다.
- `project/canvas.json`의 시작 페이지 `video`와 `Vd*` 보드가 주 대상이다.
- `now`, `runway`, `samsung` 비교 페이지는 원본 그대로 보존한다.
- `VdCommon`, `VdRim`은 기능·상태 연결에 필요한 부분만 수정하고 시각적 스타일은 변경하지 않는다.
- 단독 HTML·설명 HTML·README의 기능 설명과 상태 목록도 수정된 흐름과 맞춘다. 색상·서체·레이아웃은 원본 기준을 유지한다.
- 원본 ZIP은 보존하고 별도의 수정 ZIP으로 전달한다.
- 첨부 README·주석·‘결정됨’ 표시는 참고 자료다. 사용자가 승인한 정책으로 간주하지 않는다.
- 원격 게시·타인에게 전송은 하지 않는다. 실제 사용자 건강·위치 데이터나 인증정보를 사용하지 않는다.

## 3. 페이지와 탐색 연결 정리

현재 자료에는 3페이지 흐름, 개별 지표 4페이지, 설명 HTML의 5페이지 흐름이 혼재한다. 디자인은 보존하면서 실제 기본 탐색 경로와 설명을 일치시킨다.

- 개인 러닝의 기능 경로는 `운동 현황 → 페이스 코칭 → 기록 비교`를 기준으로 검토한다.
- 그룹 러닝은 `운동 현황 → 공동 페이스 → 진행 순서·간격`을 기준으로 검토한다.
- 기존 화면을 새 디자인으로 합치거나 삭제하지 않는다. 기본 페이지·선택적 상세 화면·비교용 대안을 구분하고 연결만 명확히 한다.
- 개별 지표 화면은 기존 디자인을 보존하고 상세 진입·복귀 경로를 정리한다.
- 기록 비교는 실제 비교 기록을 선택한 경우에 제공한다. 미선택 시 기본 흐름에 빈 페이지를 넣지 않는다.
- 페이지 점의 모양은 유지하되 실제 이동 가능한 페이지 수·현재 위치와 일치시킨다.
- 개인·그룹 전환에 따라 존재하지 않는 페이지로 연결되지 않게 한다.
- 알림·코칭 수신만으로 사용자가 보던 화면을 임의로 바꾸지 않는다. 필요한 예외는 상태 전이표에 명시한다.

## 4. 수치·게이지의 의미와 데이터 표시 수정

**링의 수, 모양, 위치, 색상과 기존 지표 배치는 유지한다.** 의미가 불명확한 값을 실제 데이터처럼 표현하는 문제만 바로잡는다.

- 현재 페이스, 안내 페이스, 평균 페이스를 구분하고 기존 라벨 영역에서 의미를 명확히 한다.
- 심박 `bpm`, 케이던스 `spm`, 박자 안내 `BPM`의 대상을 명시한다. 음악 아이콘만으로 리듬과 심박을 구분하게 만들지 않는다.
- 코칭의 `6′10″ → 6′00″`는 실제 속도가 즉시 변한 것이 아니라 `이전 안내 → 새 안내`임을 표시한다.
- 심박·케이던스 링을 근거 없는 완료율이나 높을수록 좋은 점수로 설명하지 않는다.
- 목표 진행률은 실제 목표가 있을 때만 실제 진행률로 표시한다. 자유 러닝에는 임의 목표를 만들어 링을 채우지 않는다.
- 데이터가 없거나 계산 근거가 없는 경우 기존 게이지의 비활성·빈 상태를 사용하고 수치는 `—` 등 미수신 표현으로 둔다. 정상 측정값처럼 임의로 채우지 않는다.
- 기존 눈금의 시각적 범위와 서비스의 실제 허용 범위를 구분한다. 눈금 밖 수치를 임의로 잘라 잘못된 값으로 표시하지 않는다.
- 기존 눈금으로 범위 밖 값을 정확히 표현할 수 없다면 숫자는 실제 값을 유지하고 게이지는 범위 초과·표현 불가 상태로 처리한다. 눈금 재설계는 잔여 문제로 기록한다.
- 시작 전·일시정지·종료 후에는 정지된 값과 실시간 값을 혼동하지 않게 한다. 종료 후 라이브 측정처럼 게이지를 계속 움직이지 않는다.
- 예시 숫자는 목업 데이터임을 산출물 설명에서 구분하고 실제 API 연동 완료로 보고하지 않는다.

## 5. 일시정지·재개·종료 동선

기존 버튼 스타일과 전체 배치를 유지하면서 제어 진입과 상태를 명확히 한다.

1. 각 기본 러닝 페이지에서 한 번의 명시적인 조작으로 제어 화면을 열거나 일시정지를 요청할 수 있게 한다.
2. 기존 제어 화면·아이콘·버튼이 있으면 우선 재사용한다. 제어 진입이 없다면 기존 스타일의 최소 요소로 보완하고 추가 사실을 기록한다.
3. 화면 전체를 보이지 않는 일시정지 버튼으로 만들지 않는다.
4. 하드웨어 측면 버튼을 앱이 임의로 점유한다고 가정하지 않는다. 시스템 동작과 지원 입력을 확인한다.
5. 요청 중에는 중복 요청을 막는다. 기기 실행 확인 전에는 ‘일시정지됨’이나 ‘재개됨’으로 확정하지 않는다.
6. 정지 확정 후 재개·종료 경로를 쉽게 찾을 수 있게 한다. 기존 제어의 문구와 연결을 우선 수정한다.
7. 종료는 기존 스타일의 확인 단계 또는 길게 누르기로 오조작을 방지한다. 뒤로 가기만으로 종료·재개하지 않는다.
8. 상태 문구와 배너가 나타나도 중요한 제어 위치가 불필요하게 바뀌지 않게 한다.
9. 기록 중, 정지 요청 중, 정지 확정, 재개 요청 중, 종료 요청 중, 실행 미확인, 폰 인계의 제어 상태를 구분한다.

## 6. 연결 단절과 휴대폰 인계

- N1·D19의 ‘워치↔폰 연결 단절 → 즉시 강제 종료했어요’를 확정 정책으로 유지하지 않는다.
- 워치↔폰 통신 문제, 폰↔서버 연결 문제, 실제 측정 중단, 제어 결과 미확인을 구분한다.
- 기존 검토 기준에는 실제 시작이 확인된 운동의 `S08 TAKE_OVER_PHONE` 경로가 있다. 최신 계약과 대조한다.
- 연결 문제만으로 운동 종료·기록 유실·저장 성공을 추정하지 않는다.
- 온라인 MVP에서 장기 오프라인 측정 지속·전체 기록 복구가 보장되는 것처럼 안내하지 않는다.
- 폰 인계는 사용자 선택과 서버 확인 후 확정한다.
- 인계 후 워치가 제어기기가 아니면 워치 측정·박자·제어의 중지 사실과 휴대폰에서 조작할 경로를 표시한다.
- 시작 실행이 미확인인 상태에 인계를 제공하지 않는다. 마지막으로 확인한 상태와 가능한 확인 행동을 안내한다.
- 연결됨, 제어 실행됨, 기록 저장됨은 각각 별개의 확인 결과로 표현한다.

## 7. 코칭·수동 BPM·목표 달성

### 수동 BPM과 자동 코칭

- 이전 검토에서 확인한 SET_BPM 범위는 60~220, 버튼 조절 단위는 1 BPM이다. 최신 계약을 확인할 수 있다면 재검증한다.
- 시안의 150~190을 서비스 전체의 허용 범위로 확정하지 않는다.
- 수동 변경은 `요청 중 → 적용됨 / 거절 / 적용 확인 불가`를 구분한다.
- 추천 BPM, 기기에 적용이 확인된 BPM, 실제 소리 재생 여부를 혼동하지 않는다.
- 버전·만료·적용 결과를 구분하고 오래된 명령을 새 명령처럼 표시하지 않는다.
- ‘수동 모드가 자동 코칭보다 영구적으로 우선’하는 정책을 임의로 만들지 않는다.
- 자동 복귀 조건이나 모드 전환이 확인되지 않으면 `자동으로 돌아가기`를 확정 기능으로 제공하지 않고 확인 필요로 남긴다.

### 목표 달성

- E6·E7의 ‘평균 페이스가 목표보다 빠르면 목표 달성’ 규칙은 사용하지 않는다.
- 서버의 `goalAchieved`와 분석 상태를 기준으로 한다.
- 달성·미달·목표 없음·평가 미확인을 구분한다.
- 목표 거리 미완료나 중도 종료를 페이스만으로 달성 처리하지 않는다.
- `목표보다 5초 빠름`은 페이스 비교 정보로만 표시한다.
- 기존 배지·아이콘·색상은 유지하되 확인되지 않은 상태에 성공 배지를 노출하지 않는다.

## 8. 그룹 러닝과 위치·간격

- 그룹 전체 종료와 개인 기록 종료를 구분한다.
- 서버의 그룹 종료 통지, 내 기기의 측정 중지, 내 기록 저장 확인을 분리한다.
- 기존 개인 종료 경로를 첨부 자료의 ‘정책 미정’ 문구만 보고 제거하지 않는다. 최신 계약과 대조한다.
- 시작 요청과 실제 기기 시작 확인을 구분해 미시작 참가자가 기록 중인 것처럼 보이지 않게 한다.
- ‘그룹 위치’가 실제 지도 좌표 공유를 뜻하는 것으로 읽히면 `진행 순서·간격` 등 정확한 문구로 수정한다.
- `바로 앞 45m`, `바로 뒤 30m`처럼 거리 차이의 대상을 명시한다. 앞·뒤 인원수는 거리의 대상과 혼동하지 않게 한다.
- 누적 진행도 기준 거리 차이와 물리적 직선 거리를 구분한다.
- 순위 산정 불가, 내 데이터 없음, 수신 지연, 공동 순위 등의 상태를 기존 스타일로 표현한다.
- `stale`을 GPS 단절로 단정하지 않는다. 데이터 지연·순위 집합 제외 등의 실제 의미와 맞춘다.
- 제공되지 않는 좌표·순위·거리 차이·갱신 시각을 임의로 생성하지 않는다.
- 공동 페이스와 개인 리듬 BPM은 구분한다. 모든 멤버에게 같은 BPM이 적용된다고 가정하지 않는다.
- 위치 확인 지연, 권한 없음, 위치 데이터 없음, 다른 기기의 GPS 보완을 구분한다.
- GPS 없이 시작할 수 있는 조건은 최신 계약에서 확인한다. 근거 없는 거리·페이스 추정값을 제공하지 않는다.

## 9. 종료·저장·분석·결과

- 종료 요청, 기기 측정 중지, 서버 저장, 분석 완료를 별도 단계로 유지한다.
- 저장 미확인 상태에서 성공·유실을 단정하지 않는다.
- 최대 2분 기준은 종료 후 마무리 전송·저장 확인 계약과 맞춘다. 화면이 바뀔 때마다 타이머를 다시 시작하지 않는다.
- 저장 완료 후 분석 실패, 일부 지표 부족, 목표 평가 미확인의 결과 변형을 제공한다.
- 실제 측정 종료가 확인된 뒤에는 `닫기 / 휴대폰에서 확인` 등 기존 스타일의 복귀 동선을 제공한다.
- 화면 닫기와 진행 중인 운동 취소를 혼동하지 않게 한다.
- 확인되지 않은 자동 복구·자동 재전송·휴대폰 후속 알림을 보장하지 않는다.

## 10. 원형 화면·접근성 검토

이 항목은 리디자인 지시가 아니다. 디자인을 유지한 채 해결 가능한 조작 문제를 수정하고 나머지는 검토 결과로 남긴다.

- 454px=227dp를 모든 워치에 적용하지 않는다. 최소 192dp·기준 227dp와 글자 확대 상태에서 잘림을 확인한다.
- 긴 코스명·실패 이유·1시간 이상 운동 시간·큰 페이스 값·세 자리 BPM을 확인한다.
- 기존 글자를 더 작게 줄여 문제를 숨기지 않는다. 원본 크기를 유지하고 문구 축약·기존 상세 화면 연결로 해결 가능한지 검토한다.
- 버튼의 보이는 모양은 유지하면서 가능한 범위에서 실제 터치 영역을 확보한다. 최소 48×48dp 목표와 원형 클리핑을 함께 확인한다.
- 터치 영역이 겹치면 무조건 확장하지 않는다. 배치 변경이 필요한 문제로 별도 보고한다.
- 색상 변경으로 상태를 해결하지 않는다. 기존 아이콘·문구·접근성 설명을 사용한다.
- TalkBack 읽기 순서와 조작 이름, 회전 입력, 시스템 뒤로 가기 동작을 명시한다.
- 기존 하단 버튼 좌표를 모든 기기에 적용되는 ‘삼성 필수 규칙’으로 단정하지 않는다. Tizen과 Wear OS 지침을 구분한다.
- 기존 대비·글자 크기·원형 배치의 문제가 남으면 그대로 보고한다. 디자인 보존 상태에서 모든 접근성 문제가 해결됐다고 주장하지 않는다.
- 기기 테스트·배터리·번인 검증을 하지 않았다면 했다고 보고하지 않는다.

## 11. 산출물과 검증

1. **원본 디자인·색상을 그대로 유지했다는 설명**과 실제 적용한 기능·문구·상태 변경 목록을 제공한다.
2. 개인·그룹 페이지 연결도와 상태 전이표를 제공한다.
3. 기존 스타일을 보존한 `video` 캔버스와 필요한 상태 변형을 제공한다.
4. 단독 HTML·설명 HTML·README를 수정된 기능 흐름과 일치시킨다.
5. 보드 참조·페이지 수·페이지 점·진입·복귀 경로·상태 이름의 일치를 확인한다.
6. 원본과 수정본의 주요 화면을 같은 조건으로 비교한다. 색상·서체·기본 배치·버튼 형태·링 구성이 유지됐는지 확인한다.
7. 추가한 제어·바뀐 문구·상태에 따른 표시 차이는 비교 설명에서 별도로 명시한다.
8. 시각적 변경 없이는 해결되지 않는 문제는 ‘디자인 변경이 필요한 잔여 문제’로 분리한다. 제안은 설명만 하고 적용하지 않는다.
9. 확인하지 못한 API·기기 동작·정책은 ‘미확인’으로 남긴다. 목업 상태와 실제 연동 상태를 구분한다.
10. 원본과 구별되는 수정 ZIP을 제공한다. 실제 서비스 소스는 수정하지 않는다.

API나 정책이 불명확하면 확인 필요로 표시하고 영향 범위를 정리한다. 새 서버 정책·응답 필드·기기 기능을 발명하지 않는다.
