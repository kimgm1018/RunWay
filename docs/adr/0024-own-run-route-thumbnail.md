# ADR-0024: 러닝 기록 경로 썸네일은 서버가 OSM으로 그리고 기록 주인만 토큰으로 조회한다

## 맥락

프로필 기록 탭(7.4b)은 기록·스크랩·저장된 코스를 같은 카드로 보여 준다. 스크랩·저장된 코스 카드는 [ADR-0022](0022-osm-course-thumbnail-basemap.md)에 따라 서버가 그린 OSM 평면 지도 PNG를 쓴다. 기록 카드에는 서버 그림이 없어 S15P31E105-715 기준대로 카드마다 네이버 lite 지도를 띄웠다. 같은 화면의 카드 모양이 달라지고, 동시에 띄울 수 있는 네이티브 지도 수 제한 때문에 스크롤한 카드에 지도가 늦게 뜬다.

ADR-0022는 공용 코스 그림만 만들고 F02로 토큰 없이 공개한다. 기록 경로는 본인의 GPS(출발점이 집 근처일 수 있음)라 같은 방식으로 공개할 수 없다. 앱은 지금까지 모든 이미지를 인증 헤더 없이 불러왔다. H02 명세에는 원본 GPS 대신 표시용 이미지 참조 `routePreviewImageUrl`을 주고 "이미지도 기록 접근 권한을 적용한다"는 제안이 이미 있다.

## 결정

2026-11-13 작업 요청자가 기록 카드도 스크랩·저장된 코스와 같은 서버 OSM 썸네일로 그리고, 그 그림은 **기록 주인만** 보게 하기로 정했다.

1. **생성**: 개인 세션이 처음 완료(COMPLETED)되면 커밋 뒤 코스 썸네일과 같은 단일 실행기·Route 내부 API(`POST /internal/v1/basemaps`, bbox만 전송)·Java2D 렌더러로 600×900 PNG를 그린다. 경로는 S11과 같은 표시용 선택 규칙(`SessionRouteService.displaySegments`)을 쓰고, 조각 사이를 잇지 않는다. 선 스타일·배치(가로 0.5·세로 0.30, 폭 0.42)는 코스 썸네일과 같다. 표시용 경로가 50 m 미만이거나 전국 자료 범위 밖이면 그림 없는 행만 남긴다. 기동 시 그림이 없거나 그리기 버전이 다른 완료 기록을 최신순으로 설정 건수(기본 200)만큼 채운다.
2. **저장**: `running_session_basemaps`(세션당 1행, 이미지 키, OSM 시점, 그리기 버전)에 기록하고 PNG는 이미지 볼륨([ADR-0016](0016-image-volume-storage.md))의 `images/run-route/{userId}/{uuid}.png`에 둔다.
3. **조회**: F02 `/api/v1/images/{id}`가 이 키의 그림이면 Bearer 토큰의 사용자가 세션 주인이고, 세션이 삭제되지 않았고, 사용자가 활성일 때만 준다. 그 밖은 존재를 숨기고 404 `IMAGE_NOT_FOUND`다. 공유 캐시는 막고 기기 캐시만 허용한다(`private, max-age=31536000, immutable`). 앱은 이 그림을 요청할 때만 Authorization 헤더를 붙인다.
4. **응답**: H01 항목과 H02가 `routePreviewImageUrl`(`/api/v1/images/{id}` 또는 null)을 준다. 다른 사람에게 보이는 게시물·공유 링크(H09)에는 이 그림을 주지 않는다.
5. **정리**: S09 삭제 뒤에는 조회가 막힌다. 탈퇴 정리 때 행과 `images/run-route/{userId}/` 파일을 지운다.
6. ADR-0022의 공용 코스 썸네일·공개 조회·개인 코스 `basemap=null`은 그대로다. 이 결정은 본인 기록 카드의 썸네일에만 적용한다. 그림이 없거나 불러오지 못한 기록 카드는 공용 코스 카드와 같이 밝은 바탕의 경로선만 보이며 네이버 지도를 띄우지 않는다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 본인 전용, 토큰 필수 조회 (선택) | 주소가 새어도 다른 사람이 경로·출발점을 볼 수 없다. H02 제안("기록 접근 권한 적용")과 맞는다 | 앱이 이 그림에만 인증 헤더를 붙여야 한다. 토큰이 만료된 순간에는 그림 대신 선이 보일 수 있다 |
| B. 추측할 수 없는 주소로 토큰 없이 공개 | 앱 변경이 작고 공유 캐시를 쓸 수 있다 | 주소가 로그·공유로 새면 누구나 출발점을 본다. 기록 접근 권한 원칙과 어긋난다 |
| C. 기록 카드도 네이버 lite 지도 유지(S15P31E105-715) | 서버 변경이 없다 | 카드 모양이 섞이고, 동시 지도 수 제한으로 스크롤한 카드가 늦게 뜬다. 로고·네이티브 뷰 부담이 남는다(ADR-0022 맥락) |
| D. 지도 없이 경로선만 | 가장 단순하다 | 스크랩·저장된 코스 카드와 달라 사용자가 원하지 않았다 |

## 결과

- **얻는 것**
  - 프로필의 세 탭 카드가 같은 OSM 썸네일 모양이 된다. 기록 카드에서 네이티브 지도를 띄우지 않는다.
  - 원본 GPS를 내려주지 않고 표시용 그림만 본인에게 준다.
- **감수하는 것**
  - 기록마다 Route 호출과 PNG 저장이 늘어난다. 코스 썸네일과 같은 단일 실행기를 써서 동시 부하는 늘리지 않지만 일괄 채우기 시간이 길어진다.
  - 종료 직후 그림이 생기기 전까지는 선만 보인다.
  - S09로 삭제한 기록의 PNG는 탈퇴 정리 전까지 볼륨에 남는다(조회는 막힘). 그리기 버전을 올리면 이전 PNG가 남는 문제는 ADR-0022와 같다.
  - `running_session_basemaps` 테이블, F02 인가 분기, 앱의 이미지 인증 헤더가 늘어난다.
  - 그림을 그리는 사이(Route 호출 중)에 같은 사용자의 탈퇴가 확정되면 행 저장은 거부되고 방금 쓴 PNG는 지워지지만, 그 순간 탈퇴 응답이 이미지 정리 대기(`IMAGE_CLEANUP_PENDING`)가 되거나 빈 디렉터리가 남을 수 있다. 탈퇴 이미지 정리 워커가 다시 지워 회복하므로 직렬화는 두지 않는다(2026-11-13 작업 요청자 결정).
  - 토큰이 막 만료돼 그림 요청이 401이면 그 카드는 선만 보이고, 다음에 카드가 다시 그려질 때 새 토큰으로 요청한다.
- **후속 작업**
  - 팀 확인(BE-C 기록·코스·이미지, BE-B 러닝 종료, BE-A 탈퇴 정리 담당 합의) 후 채택으로 바꾼다.
  - 삭제한 기록 PNG의 즉시 정리가 필요한지 정한다.
